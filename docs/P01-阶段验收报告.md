# P01 阶段验收报告

## 结论

`P01：Agent 蓝图与“案件设计闭环”原型` 已完成补充验收，可作为 P02 的稳定基础。

最初的 S01 至 S10 建立了行为契约、路由、状态、恢复、模板、主控和一条黄金路径。复盘发现三处证据不足：CH01 补丁未写回全部活动规范文件；模板契约与声明不完全一致；失败案例和长篇规模没有实际运行证据。P01 因此重新打开，新增并完成 S11 至 S15。

## 已实现的闭环

Agent 可以从一句种子开始，生成多个结构不同的因果方向，在用户确认前停止；得到明确确认后，建立真实时间线、知情与使用权限、社会压力、线索、嫌疑、揭示、双重结局、现实研究项和结构级章节地图。它能执行 `design-plausible` 审计，写回独立状态，生成最小恢复入口，并在关键事实变化时只撤销变化可达的状态。

P01 不生成完整正文。`manuscript-realized` 和 `final-audited` 仍是后续阶段的门禁。

## 补充任务结果

### P01-S11：规范文件同步

黄金路径的 CH01 时间窗已从“三个月每周”改为“一周集中归还”。当前配置、T08、T09、知情矩阵、C01、嫌疑路径、前四章、项目状态和恢复包使用同一新值。旧值只保留在原始种子和变更历史。局部审计与最小恢复复测通过。

### P01-S12：产物契约与校验

十五份模板均声明用途、创建路由、更新触发、状态记录位置和真相源。小说项目可以把语义接近的逻辑产物合并到一个文件，但必须在产物清单中记录规范文件和区段。

`tools/validate_p01.ps1` 可以检查模板契约、必要实例、门禁枚举、CH01 活动旧值和空文件。最终检查结果为零错误。机械校验不替代悬疑语义审计。

### P01-S13：隔离黑盒与负向评测

官方 Codex CLI 的隔离运行完成两条黑盒路径。

- 未确认运行生成三个因果方向，推荐项保持 `Provisional`，`creative-confirmed=no`，并停在方向确认门前。没有建立完整案件结构。
- 确认后运行完成十五类逻辑产物和十二章结构地图。`design-plausible=yes` 只限纸面结构；确认只覆盖用户指定范围；现实依赖保持 `partial/no`；正文与全稿门禁为 `no`。

`FAIL-01` 至 `FAIL-05` 均已实际执行并形成独立结果，覆盖人物越权知情、决定性线索后置、确认与现实混淆、虚假红鲱鱼和结局新增事实。CH01、RECOVER-01、REG-01 回归通过。

### P01-S14：长篇规模验证

`LONG-01` 建立了一个三幕三十章案件蓝图。案例包含十六个真实时间线事件、三本日志的身份和转移、十条线索、五名主要嫌疑人、六级揭示、双重结局和两处分幕连续性审计。

跨幕变更 CHG-01 将暂定时间锚从 `01:42—01:59` 改为 `01:43—02:00`，只撤销并重审受影响的时间线、线索、章节和幕审计。独立恢复只读取指南、恢复包、项目状态和变更记录，正确恢复当前方向、三幕状态、门禁、风险和唯一下一步。

长篇验证只证明案件设计、章节地图、分幕连续性、变更传播和跨会话恢复能够承受三十章规模，不证明长篇正文质量。

## 已知限制

- 决定性现实能力仍需按项目研究，P01 只管理依赖和保守退路。
- 没有正文生产、文风维护、逐章 `manuscript-realized` 验证或全稿 `final-audited`。
- 不支持多人并发修改同一项目。
- 没有 GUI、插件打包、出版、排版或投稿能力。

## P02 入口

P02 可以评审“章节规划与正文生产闭环”，但不会自动执行。P02 应把 P01 的章节地图、门禁、产物契约、变更和恢复接口作为前置输入，并新增逐章证据准备、正文实现、章后审计、结构同步、分幕连续性和全稿审计接口；全稿级 `final-audited` 留给后续阶段。
