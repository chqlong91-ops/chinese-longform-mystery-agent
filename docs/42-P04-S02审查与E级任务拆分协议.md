# P04-S02 审查与 E 级任务拆分协议

## 1. 任务身份

- task：`P04-S02：实现可执行多项目初始化器与项目级 canonical state`
- predecessor：`P04-S01-ACCEPTANCE@v001`、`P04-S01-S02-HANDOFF@v001`
- direct production evidence：`P04-AC02`、`P04-AC09`
- final acceptance owner：`P04-S10`
- current action：审查并拆分 E01—E10，不执行实现

## 2. 审查结论

S02 原目标成立，但“创建目录”和“可执行初始化器”必须分开。初始化器只有同时完成身份隔离、路径安全、确定性模板、project registry、原子 bootstrap、幂等重放、生成视图、恢复入口和跨项目污染测试，才具备产品含义。

本任务作以下收敛：

1. S02 只把种子/简报物化为可进入 P01 的空白项目，不执行案件设计、章节规划或正文生产。
2. 统一 initializer 不能依赖某个小说的目录或状态副本；真实试点选择和准入仍归 S05。
3. Agent-level registry 与 project-level registry 分离。跨项目索引只保存身份和受限生命周期，不持有项目内部 current pointers。
4. Project registry 分开保存 work、confirmation、sync、risk、gate、lifecycle 和 governance decision。目录、mtime、最高版本和 Markdown 视图不能授予 current。
5. Bootstrap 必须使用 staging、CAS/不存在性检查、单一 commit point 和 rollback/recovery；半成品目录不能成为已初始化项目。
6. E09 使用至少两个异质 synthetic fixtures 验证多项目初始化，不读取真实小说，也不把合成结果外推为试点准入。

## 3. E 级任务

`P04-S02-E01`：冻结 S02 输入 exact-set、初始化需求、非目标与验收证据合同。

`P04-S02-E02`：定义项目身份、命名、根目录隔离、路径安全与冲突规则。

`P04-S02-E03`：定义 workspace taxonomy、稿件层、结构模板与模板 exact-set。

`P04-S02-E04`：定义 project-level canonical registry schema、多维状态、current pointer 与 lineage。

`P04-S02-E05`：定义 initializer request、seed/brief normalization、bootstrap manifest 与确定性渲染。

`P04-S02-E06`：实现原子 initializer、幂等重放、single-writer、commit/rollback 与恢复。

`P04-S02-E07`：实现项目生成视图、最小恢复入口、初始 checkpoint 与唯一下一步。

`P04-S02-E08`：实现冲突、漂移、部分写入、路径越界和跨项目污染的强制失败与选择性恢复。

`P04-S02-E09`：运行多项目 synthetic 初始化、幂等、隔离、视图重建、回归和 AC02/AC09 生产证据验证。

`P04-S02-E10`：完成 S02 验收、冻结 initializer baseline 与 S02→S03 handoff。

## 4. 顺序

`E01 -> E02 -> E03 -> E04 -> E05 -> E06 -> E07 -> E08 -> E09 -> E10`

E01—E05 冻结输入和实现合同；E06—E08 完成产品实现；E09 只评价 actual output；E10 依据 actual evidence 作 S02 验收。

## 5. S02 完成条件

1. 同一入口可为至少两个 synthetic 项目建立互不污染的工作区；
2. 项目身份、根目录、registry、稿件层、结构文件和恢复入口唯一；
3. 相同 request 幂等，冲突 request fail-closed；
4. Partial write、路径越界、双 current、模板漂移和跨项目 pointer 均被阻止；
5. Generated views 可从 project registry 确定性重建，不能反写；
6. 初始 unique next 唯一指向 P01 入口，但不执行 P01；
7. P03-R1 baseline 与 Agent current registry 无污染；
8. 小说和真实项目读写保持 0/0；
9. S02 evidence 只支持 AC02/AC09 的生产证据，不授予最终 AC verdict；
10. S02→S03 handoff 不选择或准入真实试点。
