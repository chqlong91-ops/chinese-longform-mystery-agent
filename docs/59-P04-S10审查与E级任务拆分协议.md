# P04-S10 审查与 E 级任务拆分协议

## 1. 任务身份

- task：`P04-S10：完成 P04 阶段验收、冻结基线与产品交接`
- predecessor：P04-S01—S09 current task-local baseline、handoff 与 production evidence
- final acceptance owner：`P04-S10`
- acceptance scope：`P04-AC01—P04-AC12`
- current action：审查并拆分 E01—E10；不执行最终验收，不创建 P04 frozen baseline

## 2. 审查结论与调整

原任务目标成立，但必须把“证据预检”“逐项 AC 裁决”“closing validation”“阶段裁决提交”分开，避免 S10 以自己生成的报告反向证明上游能力。

1. S10 只消费 S01—S09 已冻结的 current evidence，不重新生产小说、不重新审读正文、不重跑 L6-P。
2. P04-AC01—AC12 必须逐项给出 `yes/evaluated`、`no/evaluated` 或 `not-evaluated`，并绑定直接证据、owner、证明上限与 nonclaims。
3. S09 的 `conditional-beta-candidate` 只是成熟度候选；S10 必须独立判断其条件是否允许形成产品交接，不得自动继承为阶段通过。
4. 深度试点只证明 18 章完整闭环；广度试点只证明 12 章规划与 CH04—CH07 formal 切片迁移。二者必须按实际范围裁决。
5. closing validation 可以复核 registry、关系、fingerprint、派生视图、项目隔离和失败关闭结果，但不得通过新增产物补齐缺失的 production evidence。
6. 只有 AC01—AC12 全部 `yes/evaluated`，才允许 E10 创建 `P04-FROZEN-BASELINE@v001`。任一项不满足时必须形成诚实的 not-passed checkpoint。
7. P04 baseline 只冻结 Agent 产品能力、协议、状态与验收证据，不覆盖两个试点的项目真相源、正文事实或未来创作决定。
8. S10 属 Tier 1 控制层验收，可自主顺序执行；只有真正 Tier 2 内容选择或 Tier 3 例外才停点，本任务预计不产生用户授权循环。

## 3. 输入 exact-set 与证据边界

输入限于 canonical registry、P04 阶段契约、S01—S09 current task-local acceptance/baseline/handoff、两个试点 current project registry/验收摘要、P03-R1 frozen baseline、现有 L6-P receipts、强制失败与选择性恢复 receipts。禁止读取任何小说正文、ASM payload、candidate、formal、protected source、旧会话或外部网页。

反循环规则：S10 本轮生成的 contract、matrix、report、checkpoint 或 baseline 不能作为 AC01—AC11 的上游 production evidence；只能记录裁决、聚合或提交结果。任何 AC 的直接证据缺失时不得以 S10 自身文档代替。

## 4. E 级任务

`P04-S10-E01`：冻结最终验收契约、输入 exact-set、AC01—AC12 追踪矩阵、owner、证据等级、读写预算、反循环规则、stop 与 nonclaims。

`P04-S10-E02`：运行 currentness、lineage、source fingerprint、coverage 与 owner preflight，建立非循环 final evidence graph；确认 P04 baseline 尚未创建。

`P04-S10-E03`：逐项裁决 AC01—AC03，评价阶段/项目隔离、可执行初始化和可执行创作编排。

`P04-S10-E04`：逐项裁决 AC04—AC06，评价深度完整小说闭环、广度异质迁移和范围相称的悬疑/正文质量。

`P04-S10-E05`：逐项裁决 AC07—AC10，评价低交互治理、L6-P、原子状态一致性和强制失败/选择性恢复。

`P04-S10-E06`：裁决 AC11，复核跨项目泛化、用户体验指标、配置特例、协议分叉和产品成熟度候选边界。

`P04-S10-E07`：裁决 AC12，冻结 proved、unproved、research、ambiguity、risk、nonclaims 与诚实验收规则。

`P04-S10-E08`：运行 closing integration、regression、anti-self-certification 和 failure validation，复核 Agent registry、两个项目 registry、派生视图、currentness、唯一下一步与项目隔离。

`P04-S10-E09`：装配 AC01—AC12 最终 verdict matrix、P04 stage verdict candidate 与 product maturity verdict；此步不得创建 frozen baseline。

`P04-S10-E10`：原子提交最终裁决。仅当 12/12 AC 全部 `yes/evaluated` 时创建 `P04-FROZEN-BASELINE@v001`、验收报告、产品交接与恢复入口；否则提交 not-passed checkpoint 和最小修复入口。

## 5. AC 分组与裁决责任

- E03：AC01—AC03。
- E04：AC04—AC06。
- E05：AC07—AC10。
- E06：AC11。
- E07：AC12。

每项 AC 必须记录 requirement、direct evidence refs、evidence currentness、scope、verdict、evaluation、owner、limitations 和 nonclaims。没有 direct current evidence 时只能 `no/evaluated` 或 `not-evaluated`。

## 6. 验收与基线规则

P04 阶段通过必须同时满足：

1. AC01—AC12 全部 `yes/evaluated`；
2. S01—S09 task gate 均为 current `yes/evaluated`；
3. 两个试点的项目隔离、current registry 与交接证据无漂移；
4. 深度与广度结论不超过各自实际生产范围；
5. L6-P、失败注入、选择性恢复与状态一致性证据可复核；
6. internal authorization requests 保持为零，三级权限机制未退化；
7. 不存在双 current、partial write、视图反向授权、跨项目污染或 non-unique next；
8. proved/unproved/research/ambiguity/risk/nonclaims 完整；
9. final report、product handoff、recovery entry 与 canonical registry 同一事务一致；
10. baseline 不吞并项目真相源、正文或未来产品阶段。

## 7. 失败关闭

任一输入 fingerprint 漂移、S01—S09 gate 非 current、AC 证据缺失、范围外推、S10 自证循环、项目 registry 冲突、派生视图反向授权、双 current、partial write、unique next 不唯一或必须读取小说正文时立即停止。不得降低标准、补写虚构证据、自动扩大范围或先创建 baseline 再补验收。
