# P04-S07 审查与 E 级任务拆分协议

## 1. 任务身份

- task：`P04-S07：运行广度试点的代表性跨章迁移闭环`
- project：`NOVEL-P04-BREADTH-LOSTBOX` / 《失物招领处的第六只箱子》
- predecessor：`P04-S05-TO-S07-HANDOFF@v001`、`P04-BREADTH-PILOT-ADMISSION@v001`、`P04-S06-S07-S08-HANDOFF@v001`
- project registry：`PCR-NOVEL-P04-BREADTH-LOSTBOX@v001`
- production evidence：`P04-AC05`、`P04-AC06`、`P04-AC07`、`P04-AC08` 的广度输入
- final acceptance owner：`P04-S10`

## 2. 审查结论与必要调整

S07 原目标成立，但必须防止“复制 S06”与“几章样稿冒充迁移”两类偏差：

1. 广度试点只完成异质案件设计、全书生产计划和 3—5 章代表性切片，不装配全书 ASM，不宣称第二部完整小说。
2. 切片必须形成真实跨章依赖链：线索自然出现，物件/保管链或知情权限发生转移，先前解释在后章被修正或阶段性兑现。
3. 采用物件身份、保管链、分布式局部真相和模块化多视角压力，不复制深度试点的名单、空房、证件劫持或单一限知调查路径。
4. 全书计划先于切片选择；切片选择必须说明为什么能代表迁移能力，以及不覆盖哪些全书结论。
5. E05 可先物化切片前段候选，但不单独制造确认停点；E06 在完整 3—5 章 exact-set 和跨章依赖可审阅后形成一次绑定切片的 Tier 2 内容确认。
6. 确认后 formal、CFD、结构同步、SYV、成员/边界/切片聚合自动续跑，不请求技术授权。
7. S07 生成与范围相称的 Skill-aware recovery package 和迁移差异账本；真实 project-bound L6-P 由 S08 执行。
8. 深度试点只允许读取 S06 冻结的结构比较证据，不得读取其正文、案件真相载荷或恢复包内容来反向设计广度项目。

## 3. E 级任务

`P04-S07-E01`：冻结广度试点输入、准入、隔离、REQ/AC、读取层级、允许写入面、停点预算、失败关闭与 nonclaims。

`P04-S07-E02`：建立 project-local 迁移运行基线，绑定 P01→P02→P03 编排入口、稿件层、状态事务、遥测、恢复和深浅试点结构对照合同。

`P04-S07-E03`：运行 P01 异质案件设计闭环，形成 2—3 个因果核心、推荐完整设计包、五态门禁和唯一案件方向内容停点。

`P04-S07-E04`：把 current 案件设计转换为全书生产计划，并按预先冻结的覆盖规则选择 3—5 章代表性切片、跨章依赖链、文风合同、研究能力计划和 evidence-ready 队列。

`P04-S07-E05`：运行代表性切片前段逐章生产，物化线索出现、初始误读和首个物件/权限交接；候选保持 provisional，不单独制造内容停点。

`P04-S07-E06`：运行代表性切片后段逐章生产，兑现保管链/视角转移与解释修正，完成 3—5 章 candidate exact-set、切片级审计和唯一切片内容确认停点。

`P04-S07-E07`：消费切片确认，自动完成逐章 formal/CFD/同步/SYV、成员回执、required boundary、跨章连续性、公平线索与范围终审，冻结 current representative slice set。

`P04-S07-E08`：生成与切片范围相称的 Skill-aware recovery manifest v2、checkpoint、预期语义断言和迁移差异账本；保持 `L6-P pending / owner P04-S08`。

`P04-S07-E09`：运行异质迁移、低交互、项目隔离、幂等恢复、无项目特例分叉和回归验证，形成 AC05/06/07/08 的广度生产证据与诚实 nonclaims。

`P04-S07-E10`：聚合实际证据和遥测，评价 S07 gate，冻结广度试点 baseline 与 S07→S08 handoff，并把唯一下一步切换为 `review and split P04-S08`。

## 4. 固定执行顺序

`P04-S07-E01 → E02 → E03 → E04 → E05 → E06 → E07 → E08 → E09 → E10`

普通路径计划内容停点最多两次：推荐完整案件设计对象、完整代表性切片 exact-set。内部 permit、lease、hash、研究门禁、formal、同步、边界、聚合、恢复包构建和 checkpoint 的授权请求必须为零。

## 5. 代表性切片最低证明链

切片必须同时满足：

1. 3—5 章，chapter exact-set 唯一；
2. 至少一个决定性物件或记录在两章以上保持 identity/custody 连续；
3. 至少一次知情权限或叙事视角转移改变读者可用信息，但不泄露作者知识；
4. 至少一条真线索满足 presence、visibility、interpretability 和 source-timing；
5. 至少一个初始解释在后章由外部证据修正，并保留责任 residue；
6. 切片末端产生可继续全书生产的 forward pressure，而不是伪装成全书结局；
7. 每章独立保留 evidence-ready、manuscript-realized、确认、同步和成员证据；
8. 切片级终审只授予 range-scoped verdict，不授予 full-book `final-audited`。

拆分阶段只读取 Agent current registry、S05/S06 handoff、广度项目 AGENTS/RECOVERY/project registry/bootstrap 控制层和专业 Skill；小说正文读写为 `0/0`。

执行阶段只允许写入广度试点自有 workspace、Agent `work/P04-S07`、S07 eval/checkpoint/telemetry 和声明的生成视图。禁止读取或写入深度试点正文与案件载荷、C10、legacy P01—P03 小说载荷、其他小说、外部发布目标或 protected source 覆盖面。

## 7. 验收候选

S07 通过至少要求：

1. 项目 identity、root、registry、admission 与 handoff 唯一且未漂移；
2. 案件机制与深度试点在核心因果、信息结构、社会压力和切片结构上实质不同；
3. current 案件设计和全书计划成立，但完整小说状态保持未声明；
4. 代表性切片满足最低证明链，逐章和跨章 evidence chain 完整；
5. range-scoped 因果、权限、公平、现实、连续性、人物、文风、原创和安全审计无 blocking finding；
6. 用户停点均为真实 Tier 2 内容确认或 Tier 3 例外，internal authorization requests=`0`；
7. 深度/C10/其他小说 payload over-read/write=`0/0`；

9. 无 breadth-only 编排器分叉或手工项目特例；
10. S07 证据只为 P04-AC05/06/07/08 提供生产证据，最终裁决归 P04-S10。
