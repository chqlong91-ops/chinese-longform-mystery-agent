# P03-R1 产品运行协议与 P04 入口合同

## 1. 适用范围

本协议冻结“中长篇悬疑小说创作 Agent”的控制面运行方式。它适用于 Agent 治理、状态、事务、恢复与 legacy 兼容，不直接授予任何小说项目状态。

## 2. 默认执行机制

1. Tier 1：范围内、可逆、目标明确的规划、验证和控制记录，由 Agent 自主执行。
2. Tier 2：范围内但会改变工作产物或 current 控制状态的动作，由 Agent 自主执行并生成 checkpoint。
3. Tier 3：关键真相/结局变化、不可逆或外部效果、跨范围读写、真实项目 L6 独立语义恢复，必须形成一次真实用户停点。
4. source drift、安全阻断、目标不唯一与证据冲突直接 fail-closed，不转嫁为形式化授权循环。

## 3. 状态与事务

- `state/p03-r1/canonical-registry.json` 是唯一机器可读 current source。
- Markdown、恢复摘要和 legacy projection 均为生成视图，不得反向授予状态。
- current 变化必须通过 CAS、writer lease、staging、validate、commit point、rollback 和 lease release。
- work、confirmation、sync、risk、gate 与 governance decision 独立记录，禁止互相推断。

## 4. Skill-aware recovery

- manifest v2 必须显式声明 Skill 主文件、递归依赖、project payload、forbidden reads、预算、load graph、assertions 与 unique next。
- clean recovery 必须留下 actual reads、not-read、over-read、writes、assertion 和 context disposal。
- 合成验收最多授予 `L6-S`；真实项目 `L6-P` 必须另行在项目绑定、独立上下文中评价。

## 5. Legacy 与小说边界

- P01—P03 legacy 控制材料只经 read-only adapter 进入历史投影，状态上限为 historical-reference-only。
- 小说正文、candidate、formal、ASM、BRPM 与项目状态不属于 R1 baseline。
- R1 通过不表示任何小说完成、P03 追溯通过或 release-ready。

## 6. P04 唯一入口

R1 关闭后的唯一下一步是 `review P04 definition`。该动作只允许审查和定义 P04 的目标、范围、验收标准与子任务；不得把 R1 完成解释为 P04 已启动。

## 7. 失败与回退

任何 AC 变为 not-satisfied、baseline 指纹漂移、current 出现冲突、视图漂移或 novel IO 非零时，立即 fail-closed，返回精确 owner 做最小修复和选择性重跑，不覆盖既有基线。
