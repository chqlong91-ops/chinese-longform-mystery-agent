# P04-S05 审查与 E 级任务拆分协议

## 1. 任务身份

- task：`P04-S05：建立双试点异质性合同、选择与隔离准入`
- predecessor：`P04-S04-ACCEPTANCE@v001`、`P04-PROJECT-INITIALIZER-BASELINE@v001`、`P04-ORCHESTRATOR-BASELINE@v001`、`P04-INTERACTION-RUNTIME-BASELINE@v001`
- direct production evidence：`P04-AC01`、`P04-AC02`、`P04-AC05`、`P04-AC06`
- final acceptance owner：`P04-S10`
- current action：审查并拆分 E01—E10，不执行试点选择或准入

## 2. 审查结论与调整

S05 原目标成立，但需要收紧为“合同先于种子、选择先于准入、准入先于生产”的三段式闭环：

1. 必须先冻结异质性维度、深度/广度角色和最低验证规模，之后才允许生成、接收或评价具体故事种子；不得用心仪种子反向修改异质性标准。
2. “候选”“用户选定”“workspace 已初始化”“admitted”是四个不同状态，不能互相推断。
3. 深度试点负责完整小说闭环；广度试点只负责异质案件设计、全书生产计划和具有真实跨章依赖的代表性切片，不得冒充第二部完整成书。
4. 两个试点至少在两个实质维度上不同，其中至少一个必须是核心悬疑机制或叙事结构；题目、人物姓名或表面题材差异不计入实质异质性。
5. 故事种子和初始核心方向属于 object-bound Tier 2 内容选择；只有涉及私人/跨项目数据、protected source、外部发布或其他真实 Tier 3 行为时才请求例外授权。内部路径、hash、permit、lease 和准入门禁不得形成用户授权循环。
6. 选定种子后，Agent 可以在 Tier 1 范围内使用 S02 初始化器创建隔离 workspace；每个试点必须拥有唯一 project id、根目录、registry、current pointers、恢复入口和读写预算。
7. 准入前新试点内容读写保持 `0/0`；S05 准入运行最多接触选定的 seed/brief，不读取或生成章节正文，不运行 P01/P02/P03，不执行 L6-P。
8. C10 只能使用冻结的控制层历史指标，不读取正文、候选稿、formal、ASM 或项目载荷，也不得计入两个新试点。
9. 深度与广度试点分别形成独立 admission receipt 和 handoff；S05 完成后的唯一执行入口是 S06，S07 handoff 保持冻结待命，不允许并行污染。

## 3. E 级任务

`P04-S05-E01`：冻结 S05 输入 exact-set、REQ/AC 追踪、权限边界、内容预算、非目标与失败关闭条件。

`P04-S05-E02`：定义双试点异质性维度、最低差异阈值、评分规则和合同先于种子的不可变约束。

`P04-S05-E03`：定义深度试点与广度试点的角色、最低规模、完成声明、质量范围和互不替代规则。

`P04-S05-E04`：建立故事种子候选 intake、来源/安全检查、匿名归一化、候选对象和禁止反向调参规则。

`P04-S05-E05`：按冻结合同评价候选组合，形成深度/广度推荐及 object-bound Tier 2 精确选择停点。

`P04-S05-E06`：将用户选定对象冻结为两个 pilot brief，并建立项目级悬疑、正文、现实、安全与状态质量合同。

`P04-S05-E07`：分配唯一 project identity、workspace path、coverage、source-of-truth、read/write budget 与 manifest。

`P04-S05-E08`：调用 S02 initializer 物化两个隔离 workspace、project canonical state、稿件层骨架和最小恢复入口。

`P04-S05-E09`：运行 exact-set、路径、身份、registry、C10 历史边界和跨项目污染强制失败测试，分别评价并签发 admission receipt。

`P04-S05-E10`：完成 S05 验收、冻结 pilot admission baseline，并建立互相隔离的 S05→S06 与 S05→S07 handoff。

## 4. 固定执行顺序

`P04-S05-E01 → E02 → E03 → E04 → E05 → E06 → E07 → E08 → E09 → E10`

E05 如果到达 Tier 2 内容选择停点，必须等待用户精确确认候选组合；确认后 E06—E10 属于普通 Tier 1 下游闭环，应自动继续。不得用“继续”“可以”“好”替代对象确认，也不得要求逐门技术授权。

## 5. 验收候选

S05 通过至少要求：

1. 异质性合同的冻结时间早于任何具体 seed 评价，且评价过程没有反向修改阈值；
2. 两个试点至少满足两个实质差异维度，其中一个是核心机制或叙事结构；
3. 深度/广度角色、最低规模、完成声明和 nonclaims 明确且互不替代；
4. 用户精确确认唯一候选组合，确认记录不被解释为全书、案件设计或正文确认；
5. 两个 project id、root、registry、current pointers、manifest 和恢复入口唯一且互不重叠；
6. workspace 均由统一 S02 initializer 产生，不通过手工复制 legacy/C10 状态建立；
7. admission receipt 分别绑定 current seed brief、quality contract、workspace manifest 和隔离证明；
8. C10 novel payload actual reads/writes=`0/0`，两个试点之间 over-read/write=`0/0`；
9. cross-project collision、路径逃逸、identity 重复、registry 混写和 stale selection 均 fail-closed；
10. S06/S07 handoff 各自只暴露必要项目上下文，唯一下一步为 `execute P04-S06-E01`。

这些证据只能为 AC01、AC02、AC05、AC06 提供生产证据；P04-S10 才能作最终 AC 裁决。

## 6. 非目标

本轮拆分不执行 E01—E10，不生成或选择故事种子，不创建试点 workspace，不读取或写入任何小说项目载荷，不读取 C10 正文，不运行真实 P01/P02/P03，不生成章节正文，不执行 L6-P，不授予任何 P04 AC 最终通过，也不创建 P04 frozen baseline。
