# P03-R1 原子状态事务与生成视图协议

## 1. 协议身份

- 协议对象：`P03-R1-ATOMIC-STATE-AND-VIEW-PROTOCOL@v001`
- 实现对象：`P03-R1-ATOMIC-STATE-TRANSACTION@s001`
- 视图对象：`P03-R1-DERIVED-VIEW@s001`
- 权威状态源：`state/p03-r1/canonical-registry.json`
- 适用范围：`agent-control/p03-r1`、`agent-governance/current`

本协议把状态更新定义为可验证、可恢复、可幂等重放的逻辑事务。它不把 Markdown 视图、聊天摘要或目录存在性当作事实源。

## 2. 写入权限与事务身份

Agent 本体的 Tier 1 控制状态可以自主提交；涉及候选正文确认、不可逆外部发布或高风险外部动作时，仍分别遵守 Tier 2/Tier 3。每次状态写入必须拥有唯一 `transaction_id`、`idempotency_key`、epoch、attempt、authority owner 与 writer owner。

同一 idempotency key 配同一请求指纹只能得到同一提交结果；配不同指纹必须 fail-closed。事务不能通过更换 attempt 绕过 CAS、coverage 或完整写集。

## 3. Preflight 与 CAS

提交前必须同时验证：

- 请求和 proposed registry 符合 schema；
- current registry 的 object、version、SHA-256 与 current refs 等于 expected；
- proposed registry 的 current 唯一、lineage、owner、evidence、relation、transition intent 和 unique next 成立；
- write set 目标唯一、source hash/bytes 匹配，且恰有一个 registry commit point；
- coverage 和路径均在 Agent 受控根内。

任何不满足都返回结构化 stop code，不推测修复输入，不授予新状态。

## 4. Single-writer lease

通过 preflight 后才能取得 single-writer lease。lease 绑定 transaction、request hash、owner、coverage 与 fencing token。并发 writer、过期或 owner 不匹配不能静默接管；必须恢复、释放或使用新事务身份。

正常完成、提交前 abort 和确定性恢复都必须释放 lease。无法确定 current 位于 expected 还是 proposed 时，保持 fail-closed，并把 unique next 指向 journal 检查。

## 5. Staging、bundle 与 commit point

完整 write set 先复制到同卷 staging，再形成不可变 committed bundle 和 journal。非 registry 文件即使提前物化，也因未被 current registry 引用而不产生状态权威性。`canonical-registry.json` 的原子替换是唯一逻辑提交点。

提交点前失败允许 abort/rollback；提交点后不得把旧 registry 覆盖回来，只能补齐 manifest/视图或提交显式 compensation transaction。历史 bundle、manifest 和 predecessor 不得改写。

## 6. 生成视图

current、task、recovery 三类视图只能从已验证 registry 与固定 view spec 生成。相同输入必须产生相同 payload hash 与 bundle hash。版本化 view bundle 随事务保存；固定路径 `state/p03-r1/views/` 是便于人读的镜像。

视图缺失、被人工修改或绑定旧 registry 时，处理方式是检测 drift 并从 current registry 重建。视图永不反写 registry，也不参与裁定冲突状态。

## 7. 恢复与幂等

恢复先比较 current registry hash、committed bundle、journal、manifest 和 lease：

- current=expected 且仅有 stage：安全 abort，释放 lease；
- current=expected 且 bundle prepared：可按原请求 resume；
- current=proposed：补记 committed manifest、发布/重建视图并释放 lease；
- current 既非 expected 也非 proposed：`recovery-ambiguous`，禁止自动覆盖。

Skill-aware reload 顺序和依赖清单由 P03-R1-S05 定义；完整恢复循环由 S06 定义。本协议只提供其底层事务与视图原语。

## 8. 失败关闭与非声明

失败不会自动升级 work、confirmation、sync、risk、gate 或 governance decision。事务成功也只证明 write set 和 registry 变更按本协议提交，不证明小说内容正确、用户已确认、legacy 已迁移、R1 已冻结或 P03 已重新验收。
