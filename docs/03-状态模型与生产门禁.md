# 状态模型与生产门禁

## 独立状态

项目按对象分别记录工作状态、决策状态、同步状态、风险状态、活动稿件层和五个悬疑生产门禁。不得使用一个“完成”代替这些维度。

五个生产门禁是：

- `design-plausible`：案件因果和悬疑结构在纸面上成立；
- `creative-confirmed`：用户接受明确范围的创作方向；
- `evidence-ready`：决定性现实能力已核验或有保守退路；
- `manuscript-realized`：正文通过允许视角呈现了必要事实；
- `final-audited`：全稿连续性、现实性、公平性和闭合通过。

每列使用 `yes`、`partial`、`no` 或 `not applicable`，并附对象范围和证据。任一列都不能推出其他列。

P01 主要实现 `design-plausible` 与 `creative-confirmed`，建立 `evidence-ready` 的卡片和阻塞规则。P02-S02 已实现五门禁的对象化记录、证据地址、事件、聚合和失效语义；P02-S03 已规定稿件层转换不得自动改变门禁；P02-S04 已规定 PCE sufficient、work=planned、RH ready 和 WH eligibility 均不得改变门禁；P02-S05 已实现逐章 `evidence-ready` 的现实主张、来源、七问审计、ERE、局部聚合、原子事件、退路、失效和恢复语义。`manuscript-realized` 的专业判定仍由 P02-S07 实现，`final-audited` 只保留后续全稿阶段接口。

## 状态转换

新创作事实默认是 `Provisional`。用户明确确认后只更新指定对象；“继续”只授权可逆动作。确认后若结构文件尚未更新，仍为未同步。

每次转换记录旧值、新值、触发事件、证据、范围和下一步。

## 真相源

工作流真相和叙事呈现证据分开。默认采用当前状态文件、本地规则、明确确认、最近记录、已同步结构文件的顺序决定工作版本；判断读者是否看见事实时检查正式稿本身。探索材料不能覆盖结构真相。

## 变更失效

核心责任、时间、路线、决定性线索、知情权限、现实能力和结局边界变化时，先列保留约束与影响图，只撤销变化可达的状态，再运行被触及的局部审计。旧状态不自动继承，未受影响状态不无差别清空。
