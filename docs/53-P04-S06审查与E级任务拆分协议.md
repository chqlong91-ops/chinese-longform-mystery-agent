# P04-S06 审查与 E 级任务拆分协议

## 1. 任务身份

- task：`P04-S06：运行深度试点的端到端完整小说闭环`
- project：`NOVEL-P04-DEEP-REHOUSING` / 《回迁名单上的空房》
- predecessor：`P04-S05-ACCEPTANCE-HANDOFF@v001`、`P04-DEEP-PILOT-ADMISSION@v001`、`P04-PILOT-ADMISSION-BASELINE@v001`
- project registry：`PCR-NOVEL-P04-DEEP-REHOUSING@v001`
- production evidence：`P04-AC04`、`P04-AC06`、`P04-AC07`、`P04-AC08` 的深度输入
- final acceptance owner：`P04-S10`
- current action：审查并拆分 E01—E10；不运行案件设计、研究或正文生产

## 2. 审查结论与必要调整

S06 原目标成立，但不能把“一部完整小说”压成一次无边界长任务。调整为以下顺序闭环：

1. **项目状态先于内容生产**：先把 S05 admission overlay、project-local registry、S03 编排器和 S04 交互运行时绑定为唯一运行入口；不得依赖旧聊天或手工目录状态。
2. **案件设计先于章节地图**：从已确认 seed/初始方向构造 2—3 个实质不同的因果核心，只完整展开推荐方向；将核心因果、责任、决定性线索、幕结构与事实/人的双结局绑定为一个可审阅创意对象。用户只在该对象的内容停点作精确决定，不为内部 permit、hash 或门禁授权。
3. **章节地图先于正文**：只有 current 设计包达到 `design-plausible` 且创意方向已明确，才建立全书地图、分幕边界、批次计划、文风合同、研究依赖和逐章 evidence-ready 计划。
4. **按幕批量生产但按章保存证据**：Act I、Act II、Act III 分三轮运行 P02 十二节点；用户可以一次确认一个绑定 exact-set 的批次候选，但每章仍保留独立 object/version/hash、MR、formal、确认与同步证据。
5. **确认后的技术闭环自动续跑**：候选批次精确确认后，A4/formal、CFD、结构同步、SYV、成员回执、边界和批次聚合在 Tier 1 范围连续执行，不再逐门索要授权。
6. **整书收口不替代逐章门禁**：只有 current formal chapters、required boundary/long-range audits、唯一 ASM、整书审计与选择性修复链一致，才形成全书终稿候选。
7. **S06 只准备恢复包，不执行独立 L6-P**：中段和终态 project-bound recovery package 在 S06 生成并机械/语义预检；真实 clean-session `L6-P` 由 P04-S08 独立执行。S06 不得把 package-ready 写成 recovery-verified。
8. **S07 保持隔离待命**：S06 全程禁止读取广度试点载荷、C10 或其他小说；S06 完成后只激活 S07 的 review/split 入口。

## 3. E 级任务

`P04-S06-E01`：冻结深度试点输入、项目状态、REQ/AC、权限、读取层级、内容/交互预算、停止条件与 nonclaims。

`P04-S06-E02`：建立 project-local 运行基线与 P01→P02→P03 编排地图，绑定唯一 registry、稿件层、事务、遥测、恢复和路由入口。

`P04-S06-E03`：运行 P01 案件设计闭环，形成 2—3 个因果核心、推荐完整设计包、五态门禁和唯一创意内容停点；确认前不得进入正文。

`P04-S06-E04`：把 current 案件设计转换为全书章节地图、Act I—III、生产批次、长程索引、文风合同、研究/能力计划和逐章 evidence-ready 队列。

`P04-S06-E05`：运行 Act I 逐章生产闭环，形成批次候选、内容确认停点及确认后的 formal/同步/边界/批次回执。

`P04-S06-E06`：运行 Act II 逐章生产闭环，完成中段长程与跨幕审计，并生成中段 project-bound recovery package（`L6-P pending`）。

`P04-S06-E07`：运行 Act III 逐章生产闭环，闭合事实结局与人的结局，完成全书 current formal chapter set 和终段边界/长程审计。

`P04-S06-E08`：装配唯一 ASM，执行完整整书审计、最小修复、变化影响与选择性重审，形成唯一全书终稿候选。

`P04-S06-E09`：完成全书终稿的精确用户确认、book confirmation、冻结交付候选、终态 checkpoint 与终态 recovery package（`L6-P pending`）。

`P04-S06-E10`：聚合实际证据、遥测、停点日志和失败记录，评价 S06 gate，冻结深度试点 handoff，并把唯一下一步切换为 `review and split P04-S07`。

## 4. 固定执行顺序

`P04-S06-E01 → E02 → E03 → E04 → E05 → E06 → E07 → E08 → E09 → E10`

E03、E05、E06、E07、E09 只在各自确有新的内容对象需要用户决定时形成 object-bound 停点。若同一轮未产生内容变化，不能为了维持流程而制造确认请求。普通研究、证据门禁、formal、同步、边界和恢复包构建属于 Tier 1 自动下游闭环。

## 5. 读取、写入与隔离合同

拆分阶段只读取 Agent current registry、S05 handoff/准入证据、深度项目 AGENTS/RECOVERY/project registry/bootstrap 控制层和专业 Skill；小说正文读写为 `0/0`。

执行阶段只允许写：

- `NOVEL-P04-DEEP-REHOUSING` 自有 workspace；
- Agent `work/P04-S06`、S06 eval/checkpoint/telemetry 与 canonical control evidence；
- 经事务声明的生成视图。

禁止读取或写入：

- `NOVEL-P04-BREADTH-LOSTBOX` 项目载荷；
- C10、legacy P01—P03 小说载荷或其他小说；
- 未在 current route/read manifest 声明的未来正文；
- 外部发布目标与 protected source 覆盖面。

## 6. 用户停点与低交互预算

普通路径的计划内容停点最多为：

1. 推荐完整案件设计对象；
2. Act I 批次正文候选；
3. Act II 批次正文候选；
4. Act III 批次正文候选；
5. 唯一全书终稿候选。

这是停点预算，不是强制制造五次确认。若选择非推荐因果核心、出现实质新方向或整书修复改变已确认内容，可以形成新的 object-bound 内容停点；内部 permit、lease、hash、研究门禁、formal、同步、边界、批次和 checkpoint 的授权请求必须为零。

## 7. 验收候选

S06 通过至少要求：

1. 入口 identity、root、registry、admission 和 S05 handoff 唯一且未漂移；
2. 一个 current 案件设计包同时闭合真实时间线、充分因果、信息权限、公平线索、嫌疑校正、社会压力和事实/人的双结局；
3. current 全书地图、章节/幕/批次 exact-set 与案件设计一致；
4. 每章 current formal 均有 evidence-ready、manuscript-realized、确认、同步与成员证据，批量确认不吞并章节级状态；
5. required act-boundary、cross-act 与 long-range 审计无 blocking conflict；
6. 唯一 ASM 来源可复算，整书 `final-audited=yes/evaluated`，选择性修复只重跑可达范围；
7. 全书终稿有精确确认和 book-confirmed 证据，交付候选不等于外部发布；
8. 中段与终态 recovery packages 均 current、Skill-aware、exact-set、over-read budget 明确，但 `L6-P` 保持 pending 交 S08；
9. 因果、信息权限、公平线索、现实、人物、场景、文风、原创和安全审计覆盖实际全书范围；
10. internal authorization requests=`0`，所有用户停点均可解释为真实 Tier 2 内容确认或 Tier 3 例外；
11. 深度 workspace 对广度/C10/其他小说 over-read/write=`0/0`；
12. S06 证据只为 P04-AC04/06/07/08 提供生产证据，P04-S10 才作最终 AC 裁决。

## 8. 非目标

本轮拆分不执行 E01—E10，不构造案件真相，不确定责任人、决定性线索、幕结构或结局，不运行研究，不生成或读取章节正文，不创建 ASM，不请求用户内容确认，不执行 `L6-P`，不激活 S07，不读取广度/C10/其他小说，不授予 P04 AC 最终通过，也不创建 P04 frozen baseline。
