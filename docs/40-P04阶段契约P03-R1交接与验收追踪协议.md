# P04 阶段契约、P03-R1 交接与验收追踪协议

- contract：`P04-STAGE-CONTRACT@v001`
- stage：`P04：可执行创作编排与跨项目泛化验证`
- definition：`user-confirmed / synced`
- predecessor：`P03-R1-FROZEN-BASELINE@v002`
- contract owner：`P04-S01`
- final acceptance owner：`P04-S10`

## 1. 目标

P04 要证明同一套 Agent 运行系统能够在两个新的异质项目中重复工作。系统应从故事种子建立隔离项目，按 canonical state 编排 P01、P02 和 P03，在普通路径中自主推进，在内容确认和真正的例外动作前停下，并能从文件和 manifest 恢复。

这不是再做一部示范小说。深度试点负责证明完整成书，广度试点负责证明迁移到另一类悬疑机制后仍能工作。两者共同支持产品级 Beta 候选判断。

## 2. 状态语义

阶段定义确认、任务拆分、任务执行、用户内容确认、结构同步、任务验收、试点准入和 frozen baseline 是不同事件。任何一项都不能自动推出另一项。

P04 只有在 `P04-AC01—P04-AC12` 全部由 S10 评价为 `yes/evaluated` 后，才可以创建 frozen baseline。S01 完成只证明阶段契约和追踪入口成立。

## 3. 输入和来源优先级

S01 的入口 exact-set 由 `P04-S01-INPUT-MANIFEST@v001` 冻结。输入包括工作区规则、entry canonical registry、P03-R1 baseline v002、P03-R1 产品控制协议和已确认的 P04 定义/拆分协议。

状态冲突时，canonical registry 决定 current。阶段目标冲突时，用户确认的 P04 定义优先。P03-R1 baseline 决定继承能力。README、任务页、恢复页和 generated view 只是镜像，不能反向授予状态。

## 4. 范围

P04 包含多项目初始化器、状态驱动编排器、三级停点与遥测、两个异质新试点、project-bound recovery、失败关闭、选择性恢复、跨项目指标和诚实验收。

P04 不继续修复 C10，不修改 legacy P01—P03，不建设 GUI、云服务、插件市场或模型训练系统，不自动决定 Tier 3 创意，不声称出版质量、销量或对所有悬疑类型普适。

S05 准入前，小说和真实项目载荷的读写预算为 0/0。

## 5. P03-R1 交接

P04 继承三级权限治理；把 canonical registry、原子事务、生成视图、manifest v2 和 recovery runtime 适配到隔离项目。Legacy adapter 与 C10 只作 historical reference。L6-S 只证明合成恢复，不能支持 L6-P。

完整处置记录位于 `P04-P03R1-HANDOFF@v001`。P04 不追溯改变 P03 的 `9/11 satisfied / not-passed`。

## 6. 双试点合同

深度试点从种子开始走完整案件、章节、全书、确认和恢复闭环。广度试点完成异质案件设计、全书生产计划和有真实跨章依赖的代表性切片。广度试点不能冒充第二部完整小说。

两个试点至少在两个实质维度上不同，其中一个必须是核心悬疑机制或叙事结构。具体故事种子只能在 S02—S04 完成后由 S05 选择和准入。两个项目使用独立身份、目录、registry、current pointers 和恢复包。

## 7. 验收追踪

`P04-REQ01—P04-REQ12` 与 `P04-AC01—P04-AC12` 一一绑定。每项均有生产 owner、S10 终裁 owner、所需实际证据和禁止替代证据。

文件存在、脚本全绿、用户泛泛认可、C10 历史状态或单一试点成功都不能单独支持 AC 通过。S01 冻结追踪关系，不授予任何 P04 AC 最终通过。

## 8. 证据和预算

证据等级从定义/静态验证、合成运行、真实项目运行、跨对象评价到 L6-S/L6-P 分层。每项声明不得超过证据等级上限。实际 read、not-read、over-read 和 write 必须可复算。

默认恢复只读取工作区规则、恢复入口、canonical state、近场证据和声明依赖。全稿、未来章节、旧聊天和未准入项目不是默认上下文。

## 9. 权限和停止

动作先判内部 fail-closed，再判 Tier 3，再判 Tier 2，最后进入 Tier 1。

Tier 1 覆盖内部规划、研究、可逆候选、审计、验证、状态事务，以及内容确认后的普通 formal、同步和传播。Tier 2 只处理实质创意方向、正文候选和全书终稿确认。Tier 3 处理核心因果/责任/决定性线索/幕结构/结局变化、protected source 覆盖、跨项目或外部扩张、发布、破坏性动作和把真实项目载荷送入独立 Agent/L6-P。

Source drift、双 current、缺证据、over-read、partial write、目标歧义或非唯一下一步属于内部阻塞。用户授权不能绕过这些阻塞。相同 blocker 连续两次没有证据变化时进入 no-progress，由唯一 owner 选择 resume、repair、replan、rebuild 或 abandon。

## 10. S 级执行和验收责任

`S02` 实现初始化器和项目 canonical state。`S03` 实现 P01→P02→P03 编排器。`S04` 实现停点、自动闭环和遥测。`S05` 选择并隔离准入试点。`S06` 完成深度试点。`S07` 完成广度试点。`S08` 运行 L6-P、强制失败和选择性恢复。`S09` 评价泛化与体验。`S10` 作最终验收和 baseline 决定。

每个 S 任务开始前重新审查上游 actual 输出，再拆分 E 任务。拆分不等于执行。

## 11. 失败关闭

以下情况禁止授予阶段或任务状态：输入漂移、双 current、跨项目污染、能力处置缺失、AC owner 缺失、证据循环自证、证据等级越界、预算超限、内部授权循环、L6-S/L6-P 混同、非唯一下一步或 baseline 回归失败。

失败记录最小补救和唯一 owner，不降低验收标准。

## 12. S01 完成边界

S01 通过只允许把唯一下一步切换到“审查并拆分 P04-S02”。它不执行 S02，不选择试点，不读取小说，不授予 L6-P，不创建 P04 frozen baseline，也不授予任何 P04 AC 最终通过。
