# P02 变更传播、分幕连续性与恢复验证协议

## 目标与边界

本协议在 S08 直接结构同步之后建立三个相互独立、可验证、可中断恢复的轨道：

`Track-D 变更传播 -> Track-B 分幕边界连续性 -> Track-R 干净上下文恢复`

S09 只管理 current SIH 的影响图、选择性失效、传播运行/验证、幕边界快照/审计、恢复包/白名单装载/重建、跨轨冲突和隔离文件级验证。它不重新判定 S08 sync，不生成或修改正文，不执行真实用户确认，不替代 P01/S05/S07 专业审计，不执行 S10 三章试点或 P02 总验收，也不授予 `final-audited`。

## 五类独立事实

| 事实 | 唯一规范证据 | 不代表 |
|---|---|---|
| sync-verified | S08 current SYV + direct required targets actual matched | 下游消费者已传播 |
| propagation-verified | S09 current PVV + required consumers actual/current/post-run matched | 分幕或恢复通过 |
| act-boundary-verified | S09 current BAV + 唯一 boundary/member versions/BSS + closed findings | 全书连续或 final |
| recovery-reconstructed | S09 current RTV + manifest/access log/oracle，前三维 yes | 语义充分或真实新 Agent 会话 |
| final-audited | P02 不授予 | S09 任一结果 |

工作完成、计划 ready、写命令成功、事件存在、摘要一致、机械退出码或用户泛化反馈不能替代规范证据。

## 运行顺序

1. S08 形成 current SIH，声明 actual changed targets、relations、checkpoint、conflict、preserved/new claims 和待验证项。
2. Track-D 复核 SIH/SYV/owner actual，建立 CIR 与 current IGS。
3. 按显式 edge/version/scope/dimension 计算 affected set，形成 PEI 与 PVP。
4. PVR 逐 consumer 记录 before/intended/actual/checkpoint，PVV post-run 聚合。
5. 对唯一幕边界建立 BAR/BSS，运行 C01-C12、反事实、BAF 和 BAV。
6. 根据 current checkpoint 构建 RPM，clean loader 只读白名单并输出 RRR/RTV。
7. 任一轨发生 partial/stale/conflict/no-progress，按 E07 恢复合同处理。
8. S9H 把协议、隔离证据、未证明项和试点前置交给 S10。

任何轨道可因任务范围 not-required，但必须有证据；任何单轨通过都不能跳过另一轨或提升五门禁。

## S08 入口

必需输入：current SIH/SYV、changed targets old/new/version/fingerprint、applied/partial/compensated/remaining、direct consumers/relations/evidence、preserved/new claims、失效维度、risk、checkpoint、conflict/no-progress 和三轨待验证项。

- SIH/SYV 缺失或 actual 不符：Track-D blocked/source-conflict，回 S08。
- 无 actual change 且无 invalidation event：propagation-not-required，不创建空 PVR。
- direct consumers 不证明 transitive set 完整；IGS 必须复算。

## 版本化影响图

### 节点

story-truth、epistemic、mystery-structure、continuity-ledger、chapter-plan、reality、manuscript、audit、decision、sync、workflow-state、recovery 共 12 类。

### 边

`derives-from`、`consumes`、`realizes`、`constrains`、`supersedes`、`invalidates`、`aggregates`、`mirrors`、`authorizes`、`hands-off-to`、`verifies` 共 11 类。每条边必须声明 direction、source/target version/scope/location/fingerprint、dimension transfer、required/optional、evidence、currentness、stop 和 risk。

路径、标题/关键词相似、文件邻近或聊天记忆不能单独创建 required edge。

### 可达算法

遍历键为 `(node, version, scope, dimension)`：

1. 从 current actual seeds 有序入队；
2. 只读取 current、版本/scope 匹配且声明 dimension transfer 的 outbound edge；
3. 无 scope overlap 列 excluded；unknown decisive relation 列 blocked；
4. visited set 防循环，alternate path 保留；
5. 输出 direct/transitive/required/optional/excluded/unknown；
6. 声明集合与计算集合 diff，检测 under/over-reach。

wildcard、旧边、悬空 required node、cross-version、互斥 relation、双 current 一律停止相关聚合。

## 选择性失效与传播

affected item 必须精确到 object/version/scope/dimension。八类维度：design、evidence、work、manuscript、confirmation、sync、risk、recovery。

disposition：preserve、invalidate、revalidate、replan、repair、block、not-applicable。

- 失效保留历史值/事件，将 current lifecycle/evaluation 标 stale；不删除或改写为 no。
- 未触及对象以 `PEI-<IGS-ID>-<seq>@vNNN#scope` 证明 preserved-current/revalidation-required。
- 计划、运行、验证分权：PVP ready 不等于 PVR completed，PVR completed 不等于 PVV verified。
- S09 只写 A1 影响/状态/记录或在隔离 A2 root 写 fixture；正文 A3、真实结构/确认 A4 仍回 owner。

PVV item：matched、preserved-match、missing、mismatched、over-invalidated、under-invalidated、source-stale、target-stale、unverifiable、conflict。

PVV aggregate：verified、partial、pending、stale、conflict、not-required。只有全部 required matched/preserved-match、必要重验 current 且无异常，才能 propagation-verified。

## 分幕边界连续性

Boundary object 绑定 from/to act、covered CH/CC/current formal versions、last-before/boundary/first-after、structure/ERE/MR/CFD/SYV/PVV baseline 和 source fingerprints。

BSS 分四层：actual-story、character-epistemic、reader-state、manuscript-realization；每层记录 before/at/after、stable source/version/location/currentness。

### C01-C12

1. 时间与因果顺序。
2. 地点、路线与障碍。
3. 物件身份、复制/转移与终态。
4. 凭证、权限与权威。
5. 地址、容量、数量与集合。
6. 人物知识、披露/使用和正常行为。
7. 线索生命周期与公平六项。
8. 嫌疑进入、外证校正、退出和 residue。
9. 揭示、工作答案、矛盾、新问题与供述依赖。
10. 现实能力、字段、时效、权限和命题边界。
11. 章节/场景 delta、关系/危险/决定与社会压力。
12. 稿件、门禁、确认、sync 与 propagation currentness。

missing input 先标 unresolved-input。BAF 必须有 stable/missing location、观察、规则、后果、severity、affected dimensions、owner、minimum repair、新主张和 recheck scope。

修复回 P01/S04/S05/S06/S07/S08；若产生 delta，先 Track-D 后新 BAU。旧 BAV 不继承。

BAV：verified、findings-open、repair-pending、recheck-required、blocked、stale、conflict。verified 只证明声明边界。

## 恢复包与干净上下文

RPM 记录 project/root/scope、generated checkpoint/event、active task/track/object/version/layer/scope、严格 file entries/read order、stable section/SHA-256、oracle、allowed root/path policy、expiry、non-grants 和 unique next action。

装载顺序：workspace rule -> active protocol -> state/pointers -> checkpoint/events -> current track objects -> source evidence -> 最小 structure/prose/records -> reconstruct -> compare。

默认不读全稿、全部 raw/revised、未来正文、所有历史、旧聊天、网络、环境秘密或 sibling projects。manifest 外读取使 RTR invalid。

RRR comparison：matched、missing、mismatched、unexpected、ambiguous、not-loaded。

RTV 五维：package-valid、files-reconstructed、workflow-resumable、semantic-context-sufficient、clean-agent-session。`recovery-reconstructed` 只要求前三维 yes、undeclared reads=0、无 conflict；后两维不能从机械测试推断。

missing/hash drift/path escape/双 current/checkpoint gap/非唯一 next/pack drift 均 fail-closed。

## 冲突、恢复与无进展

十类 conflict：source、target、graph、boundary、pack、checkpoint、authority、safety、isolation、recovery。

七种恢复动作：resume-forward、replan-impact、rebuild-pack、repeat-audit、route-owner、request-A4、abandon-run。

同一 root-cause signature 连续两轮没有新增 matched、减少 remaining/blocker、减少 unknown 或推进 checkpoint，即 no-progress，停止自动循环。

Track-D verified/not-required 才能支持相关 BAR ready；boundary repair 产生 delta 时先 Track-D；Track-R 只重建 current entry，不改变 PVV/BAV。

## 隔离文件级证据

每次试验从固定 baseline 复制到经绝对路径验证的系统临时 run root，写入只限 run root。保存 before/intended/actual/post-read/checkpoint/oracle；运行后重算 baseline fingerprint，再安全清理 temp workspace。

已运行 8 次：未触及保留、局部传播、选择性失效、partial resume、clean boundary、植入矛盾、最小恢复、hash drift fail-closed。8/8 passed，baseline 8/8 unchanged。

隔离证据只证明文件级机制；不证明真实项目、用户确认、新 Agent 语义恢复或三章闭环。

- boundary：boundary-request/snapshot/audit、finding-opened/routed、recheck-required、boundary-verified；
- recovery：recovery-pack-created/invalidated、test-started、read-recorded、reconstruction-recorded、recovery-reconstructed/test-invalidated；
- common：run-interrupted/partial/stale/conflict/no-progress、checkpoint-created、owner-handoff、a4-required、run-abandoned、isolation-conflict、s9-handoff-created。

一条事件只改变一个对象/version/scope 的一个维度；applied 历史不原地改写。
