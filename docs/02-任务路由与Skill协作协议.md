# 任务路由与 Skill 协作协议

## 路由规则

每轮只设一个主路由。主路由决定当前目标、最小读取、主要产物和停止条件；辅路由只处理独立的附加职责。

判定顺序：恢复或初始化、关键变更、审计或修复、真相转换、种子构造、章节地图、研究或正文交接。

| 路由 | 用途 | 主要产物 |
|---|---|---|
| `R-BOOT` | 初始化新项目 | 配置、状态和恢复入口 |
| `R-CONSTRUCT` | 从种子建立因果核心 | 创作简报、候选真相和风险 |
| `R-TRANSFORM` | 将已知真相转为悬疑 | 时间线、知情、线索、嫌疑和揭示 |
| `R-AUDIT` | 审计结构或局部问题 | 具体发现、影响和最小修复 |
| `R-REPAIR` | 修复明确故障 | 保留约束、修复差异和重审范围 |
| `R-MAP` | 生成结构级章节地图 | 章节信息任务和第二阶段入口 |
| `R-CHANGE` | 处理决定性事实变化 | 影响、状态撤销和重审计划 |
| `R-RECOVER` | 跨会话恢复 | 当前快照、冲突和下一步 |
| `R-ABSTRACT` | 抽象参考作品机制 | 高层功能、结构改造和相似风险 |
| `R-RESEARCH` | 管理现实依赖 | 能力卡、研究问题和保守退路 |
| `R-HANDOFF` | 处理 P01 范围外请求 | 可做部分、边界和后续入口 |

## 组合顺序

`恢复/初始化 -> 变更识别 -> 构造或转换 -> 审计 -> 修复 -> 现实依赖 -> 章节地图 -> 正文交接`

前置条件已满足时引用证据，不重复执行；部分满足时只补缺口；可探索但未过门禁时只产出隔离的低承诺材料；硬门禁未过时停止受影响分支。

## Skill 分工

- `craft-social-mystery`：悬疑因果、知情权限、线索、嫌疑、揭示、公平推理和修复。
- `novel-project-strategy`：工作区、恢复、状态、确认、稿件层和结构同步。
- `novel-writing`：章节、场景、人物引入、正文、修改和文风。P01 只调用其章节结构判断，不生产正式整章。
- Agent：选择路由和 Skill，维护文件和状态，处理交接。

调用 Skill 时必须提供当前路由、决策状态、对象范围、最小文件、预期产物、门禁和保留约束。Skill 的结论只在其职责范围内有效。

## 路由执行契约

每条路由必须回答四件事：

1. 读什么：完成任务所需的最小文件；
2. 做什么：当前路由的核心动作；
3. 写什么：稳定产物、状态、风险和记录；
4. 停在哪里：通过、待确认、需修复、研究阻塞或阶段交接。

路由收尾时记录实际修改文件，分开更新工作、确认、同步和悬疑生产状态，并给出一个主下一步。

## 范围护栏

路由不能把 P01 扩张为完整正文、多 Agent、GUI、出版或投稿工程。`R-HANDOFF` 保留已经完成的案件设计，说明后续所需门禁和入口。

详细的每路由读写停表见 `work/P01-S02/04-路由执行契约.md`。
