# P03-R1 三级权限与用户交互停点协议

- governance object：`GOV-AGENT-THREE-TIER@v002`
- predecessor：`GOV-AGENT-THREE-TIER@v001`
- 状态：current
- 生效日期：2026-08-26

## 目的

用户负责内容确认和真正的高影响决定。Agent 负责范围内的可逆工作和内部事务，不把 permit、lease、A0—A5、checkpoint 或 hash 核验变成用户审批流程。

## 判定顺序

每个动作先绑定唯一目标和范围，再按以下顺序分类：

1. 输入缺失、目标不精确、安全/证据阻塞或 source drift：内部 fail-closed。
2. 范围扩张、不可逆、外部影响、重大内容变化或显著风险：三级例外授权。
3. 正文或创意方向确认：二级确认。
4. 已圈定范围内的可逆动作：一级自主。

每个动作只能有一个结果。fail-closed 是运行状态，不是第四权限等级，也不向用户请求授权。

## 一级自主

一级覆盖最小恢复读取、规划、研究、证据预检、可逆候选稿生成或修复、审计、验证、状态记录，以及候选稿确认后的 formal evaluation、晋升、结构同步、SYV、L4-C、边界和批次聚合。

Agent 本体内的协议、schema、夹具、验证器和不含真实小说载荷的合成 clean-session 也属于一级。

一级路径连续运行到可验证结果、二级/三级停点或内部阻塞。不得停在 permit、lease、A0—A5 或普通 hash 检查上索要授权。

## 二级确认

二级只用于正文候选稿、明显不同的创意方向、章节内容和全书终稿。

默认提示显示作品/章节或决策名称、短版本、改动范围或选项差异、不包含事项和一句确认请求。完整 object/version/hash 在审计层绑定；只有对象可能混淆或用户要求时才展开。

“继续”“可以”“好”“不错”表示继续推进，不自动成为内容确认。用户明确确认当前唯一候选或选项后，未触发三级或内部阻塞的下游流程自动执行。

## 三级例外授权

以下动作需要明确授权：

- 改变核心因果、责任人、关键真相、决定性线索身份、世界规则、幕结构或结局；
- 覆盖、删除或回写 protected source，或执行其他不可逆/破坏性动作；
- 扩展到未圈定项目、私人数据、新外部系统或明显更高的成本和风险；
- 对外发布、传输、交付或产生外部影响；
- 把真实项目载荷带入新的独立 Agent/L6 上下文。

合成、只读且不含项目载荷的 clean-session 属于一级。

三级提示说明动作、影响、可逆性和建议。需要执行时提供一条紧凑授权语句，包含目标/范围、允许动作、关键禁止项、失败关闭和退出要求。它不复制完整内部证据链。

## 内部阻塞

安全硬边界、违法或有害请求、必要证据不足、source drift、双 current、目标不精确、路径不安全和无法证明的状态不能靠授权绕过。Agent 报告阻塞、未执行动作、已保护状态和唯一补救，不生成无效授权语句。

## 用户视图

默认摘要最多包含六项：结果、当前对象、实际变化、验证、需要用户做的事、唯一下一步。permit、lease、A0—A5、完整 hash、controller、读取账本和重复 non-grants 默认隐藏，可按需展开。

用户视图是派生结果，不是状态真相源，不能反向授予 confirmation、sync、gate 或 current。

## 审计与兼容

内部审计仍记录 action、object/version/hash、scope、actual reads/writes、证据、decision 和 next。旧长授权书、A0—A5、permit 和 lease 保留为 historical intent/evidence，不再定义默认用户节奏，也不迁移到新对象。

`docs/25-三级权限与自主执行协议.md` 保留为 v001 historical predecessor。S03 将建立 canonical governance state；S04 将实现原子提交。在此之前，本协议与 `GOVERNANCE-ACTIVATION@v002` 共同构成治理 current 的文件级入口。

## Nonclaims

本协议不创建 canonical registry，不证明跨文件原子提交，不授予任何小说、章节、全书、release 或 recovery 状态，不追认 P03-AC08/P03-AC10，也不创建 R1/P03 frozen baseline。
