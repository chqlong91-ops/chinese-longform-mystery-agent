# P04-S04 审查与 E 级任务拆分协议

## 1. 任务身份

- task：`P04-S04：实现三级停点、自动下游闭环与低交互运行遥测`
- predecessor：`P04-S03-ACCEPTANCE@v001`、`P04-ORCHESTRATOR-BASELINE@v001`、`P04-S03-S04-HANDOFF@v001`
- direct production evidence：`P04-AC07`、`P04-AC11`
- final acceptance owner：`P04-S10`
- current action：审查并拆分 E01—E10，不执行实现

## 2. 审查结论

S04 原目标成立，但必须把“单步编排”和“运行体验”分层：S03 继续决定唯一 route、owner、stop 和原子状态提交；S04 只在其上建立有界 run session，自动连续调用 Tier 1 步骤，在 Tier 2、Tier 3 或内部 fail-closed 时停止，并生成可恢复 checkpoint、低噪声用户摘要和可聚合遥测。

本任务作以下收敛：

1. 每个底层动作仍是 S03 的单步原子事务；S04 不绕过 CAS、single-writer、idempotency 或 post-read verification。
2. 用户停点只允许 Tier 2 内容确认和 Tier 3 真正例外；内部 permit、lease、hash、A0—A5 和普通门禁不得变成用户授权。
3. 内部 fail-closed 优先于权限分级；source drift、double current、missing evidence、unsafe scope、over-read、partial write 和 non-unique next 只能交给具名内部 owner。
4. Tier 2 必须绑定唯一内容对象与确认范围；泛泛的“继续/可以/好/不错”不构成确认。明确确认后，普通 formal、同步和传播自动恢复 Tier 1。
5. Tier 3 必须说明动作、影响、可逆性和建议；只有决定执行时才输出紧凑授权语句，且授权不能绕过内部阻塞。
6. 自动续跑必须有 step、time、write 和重复 blocker 预算；达到预算时创建可恢复暂停，不伪造成功。
7. 遥测以事件账本为事实源，用户摘要是派生视图；不得由摘要反向授予 confirmation、sync、gate 或 current。
8. E09 只运行 synthetic interaction sessions，不选择或准入真实试点，不读取或写入小说，不执行 L6-P。

## 3. E 级任务

`P04-S04-E01`：冻结 S04 输入 exact-set、REQ07/REQ11、非目标、证据等级与读写预算。

`P04-S04-E02`：定义 run session、interaction event、stop checkpoint、resume token 与 telemetry envelope。

`P04-S04-E03`：实现内部 fail-closed、Tier 3、Tier 2、Tier 1 的唯一 interaction decision classifier。

`P04-S04-E04`：实现有界 Tier 1 auto-continue supervisor、自动下游闭环和运行预算。

`P04-S04-E05`：实现 object-bound Tier 2 confirmation checkpoint、歧义拒绝与确认后自动续跑。

`P04-S04-E06`：实现 Tier 3 exception stop、影响披露和紧凑可复制授权语句生成。

`P04-S04-E07`：实现内部 blocker/no-progress 的具名处置、暂停恢复和无授权闭环。

`P04-S04-E08`：实现低交互 telemetry ledger、指标聚合与最多六项的用户摘要派生视图。

`P04-S04-E09`：运行 synthetic 普通路径、Tier 2/Tier 3、误停点、阻塞、重放和恢复回归，形成 AC07/AC11 生产证据。

`P04-S04-E10`：完成 S04 验收、冻结 interaction runtime baseline 并建立 S04→S05 handoff。

## 4. 固定执行顺序

`P04-S04-E01 → E02 → E03 → E04 → E05 → E06 → E07 → E08 → E09 → E10`

不得先写用户提示再补状态语义；不得在没有 checkpoint、resume、预算和 telemetry 的情况下声称“自动闭环”。

## 5. 验收候选

S04 通过至少要求：

1. 每个动作恰好分类为 internal stop、Tier 3、Tier 2 或 Tier 1；
2. Tier 1 普通路径无需用户授权，能跨多个原子步骤自动推进至唯一 stop/terminal；
3. Tier 2 只为唯一内容对象停一次，明确确认后下游 Tier 1 自动恢复；
4. 泛泛确认、错误对象、stale confirmation 和重复确认均不得授状态；
5. Tier 3 授权提示只在真实例外出现，且包含影响、可逆性、建议、scope、关键禁止项和 fail-closed；
6. 内部阻塞不生成授权语句，重复两次无证据变化进入 no-progress；
7. run budget 到限形成 checkpointed pause，可从 canonical state 和 manifest 恢复；
8. telemetry 能复算自动推进率、Tier 2/Tier 3/internal stop 构成、无效授权请求、恢复耗时和人工修复量；
9. 用户摘要最多六项且不泄露内部 permit/lease/hash 细节，不反向授状态；
10. synthetic 回归证明 zero internal authorization requests、deterministic stop/resume、novel reads/writes=`0/0`。
