# P04-S09 审查与 E 级任务拆分协议

## 1. 任务身份

- task：`P04-S09：完成跨项目泛化、用户体验与产品成熟度审计`
- predecessor：P04-S02—S04 产品运行基线、P04-S05 双试点合同、P04-S06/S07 试点基线与 P04-S08 恢复验收移交
- direct production evidence：`P04-AC06`、`P04-AC11`
- honest-acceptance input：`P04-AC12`
- final acceptance owner：`P04-S10`
- current action：审查并拆分 E01—E10；不执行审计，不读取小说正文，不授予 P04 最终结论

## 2. 审查结论与调整

原目标成立，但必须把“项目范围差异”“泛化能力”和“产品成熟度”分开评价，避免把深度试点的一部完整小说与广度试点的代表性切片做虚假等量比较。

1. 深度试点证明端到端完整闭环；广度试点证明异质机制、统一初始化与代表性跨章迁移；C10 只能作为冻结历史交互成本参照，不计入两个新试点，也不得读取其正文。
2. 泛化成立需要同一初始化器、编排器、三级停点、canonical state、RMv2 与 L6-P 合同跨两个新项目复用；配置差异可以存在，项目专用协议分叉必须逐项登记。
3. 内容质量只使用 S06/S07 已有审计、确认和 baseline 证据。S09 不重新审读正文，也不把广度切片外推为完整成书质量。
4. 体验评价使用可复算指标：初始化成功率、常规路径自动推进率、用户停点构成、内部授权请求、恢复成功率、状态漂移、选择性重跑范围、人工修复量和项目特例数；主观“好用”不能独立裁决。
5. synthetic 遥测与真实试点遥测分列。synthetic 证明运行时行为覆盖，真实试点证明产品载荷表现；两者不得混成一个分母。
6. 恢复与失败结论只消费 S08 已冻结 receipt 和矩阵，不再创建独立 Agent、不再运行 L6-P、不修改 recovery package。
7. S09 可以形成 maturity verdict candidate（`beta-candidate`、`conditional` 或 `not-ready`），但不得把候选改写成 P04 final verdict 或 frozen baseline。
8. S09 全部为 Tier 1 控制层审计，不产生正文确认或授权停点；遇到证据缺失、口径不可复算或项目范围被错误外推时 fail-closed。

## 3. 输入、读取与比较边界

默认读取集限于 Agent canonical registry、P04 合同、S02—S04 基线/遥测、S05 双试点合同、S06/S07 baseline 与质量/交互摘要、S08 baseline/handoff/production evidence，以及 C10 已冻结的控制层历史摘要。禁止读取任何小说正文、ASM payload、candidate、formal、protected source、旧会话或外部网页。

比较单元分为：

- 产品基础：初始化器、编排器、三级停点、状态事务与恢复协议；
- 深度载荷：18 章完整小说闭环；
- 广度载荷：12 章全书计划与 CH04—CH07 formal 跨章切片；
- 历史参照：C10 授权循环和恢复治理缺陷的冻结控制层记录，只用于前后差异解释。

## 4. E 级任务

`P04-S09-E01`：冻结 S09 审计契约、输入 exact-set、比较单元、指标词典、证据等级、读写预算、停止条件与 nonclaims。

`P04-S09-E02`：建立深度试点、广度试点与 C10 历史参照的范围归一化协议，标记可比项、仅项目内项和禁止外推项。

`P04-S09-E03`：构建 cross-project generalization matrix，区分通用 runtime、合法配置差异、项目特例、项目专用协议分叉和未证明能力。

`P04-S09-E04`：审计统一初始化、P01→P02→P03 编排、canonical state、原子事务、派生视图和项目隔离在两个新试点上的复用证据。

`P04-S09-E05`：聚合 synthetic 与真实载荷的自动推进率、Tier 2/Tier 3/internal stop、内部授权请求、确认后自动闭环、无效确认和人工修复成本；分母与范围必须可复算。

`P04-S09-E06`：聚合三次 L6-P、八类强制失败与八项选择性恢复，计算恢复成功率、over-read、状态漂移、全书重跑数、受影响范围和协议分叉数。

`P04-S09-E07`：建立与实际范围相称的内容质量对照，核验深度全书和广度切片的因果、信息权限、公平线索、嫌疑校正、人物、场景、文风、安全与结局证明上限。

`P04-S09-E08`：执行产品体验审计，检查恢复入口、唯一下一步、停点解释、最多六项用户摘要、错误补救、术语负担和内部治理泄漏；所有判断须绑定事件或状态证据。

`P04-S09-E09`：形成 AC06/AC11 production-evidence pack、异常/特例注册表、指标仪表板、proved/unproved/research/ambiguity/risk/nonclaims 与 maturity verdict candidate。

`P04-S09-E10`：评价 S09 task gate，冻结 S09 task-local baseline 与 S09→S10 handoff；保持 P04-AC01—AC12 final verdict 为 `not-evaluated / owner P04-S10`，唯一下一步切换为 `review and split P04-S10`。

## 5. 指标口径

1. 初始化成功率：统一初始化入口成功建立合规隔离项目数 / 尝试初始化的新试点数；不得把手工补录后的目录存在算作首次成功。
2. 常规路径自动推进率：Tier 1 自动完成步骤 / 所有可自动或需停点的有效步骤；synthetic 与真实载荷分别报告。
3. 用户停点构成：Tier 2 内容确认、Tier 3 真正例外、internal stop 分列；internal stop 不得包装成授权请求。
4. 恢复成功率：取得合格 L6-P receipt 的计划恢复点 / 实际运行恢复点，并同时报告 assertions、over-read、writes 与 context disposal。
5. 状态漂移：双 current、未登记 partial write、确认/同步误继承、视图反向授权、跨项目污染和 non-unique next 的实际发生数；注入且被 fail-closed 的 fixture 单列，不计作产品状态漂移。
6. 选择性重跑范围：修复后实际重跑对象 / 可达受影响对象，并报告 full-book rerun 数。
7. 人工修复量：用户或操作者为内部状态、hash、permit、lease、恢复包和视图所做的人工动作；正常 Tier 2 内容判断不计入内部修复。
8. 项目特例数：必须由项目内容或结构差异解释的配置项；项目专用 runtime/protocol fork 另列，不能混同。

## 6. 验收条件

S09 只有同时满足以下条件才能通过自身 task gate：

1. 三参照范围、证据等级、可比与不可比项明确，广度切片没有被外推为完整小说；
2. 两个新试点的统一初始化、编排、状态、交互和恢复能力均有 current evidence；
3. 通用能力、合法配置差异、项目特例、协议分叉和未证明能力分别登记；
4. AC11 规定的七类最低指标全部可复算，并补充内部授权请求和人工修复量；
5. synthetic 与真实试点指标分列，分母、范围、时间点和证据源明确；
6. 深度全书与广度切片质量结论均不超过各自 current 审计范围；
7. C10 只作为冻结控制层历史参照，正文读写均为零；
8. 恢复统计精确反映 3/3 L6-P、30/30 assertions、over-read/writes 0/0、8/8 fail-closed 和 8/8 selective recovery；
9. 用户停点均可解释，internal authorization requests=0，不新增逐 hash/permit/lease 授权循环；
10. maturity verdict 仅为 S10 输入，P04 final verdict 与 frozen baseline 均未授予；
11. proved/unproved/research/ambiguity/risk/nonclaims 完整且互不推断；
12. S09→S10 handoff 的 owner、stop、唯一下一步和证据 exact-set 唯一。

## 7. 失败关闭

任一输入 fingerprint 漂移、指标分母不唯一、synthetic/真实载荷混算、广度范围外推、C10 正文读取需求、项目专用协议分叉未登记、质量结论缺少 current evidence、状态出现双 current 或 unique next 不唯一时立即停止。不得用主观评价、旧聊天或补写结论填补证据缺口，只记录最小补救、owner 和 checkpoint。
