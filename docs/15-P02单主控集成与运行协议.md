# P02 单主控集成与运行协议

## 1. 协议身份

- 协议：`P02-CONTROLLER-PROTOCOL@v001`
- 阶段：P02“章节规划与正文生产闭环原型”
- 冻结日期：2026-08-20
- 适用范围：以 P01 current 案件蓝图和章节地图为输入，运行逐章规划、现实门禁、正文候选、审计/修复、formal 晋升、用户确认、结构同步、变化传播、分幕和恢复。
- 非授权：本协议不授全稿 `final-audited`、出版级质量、专业法律/医学结论、多人并发改稿或无人值守整书。

## 2. 单主控边界

单主控只负责识别 current 对象、选择一个主路由、计算最小上下文、检查授权/门禁、交接唯一 owner、限制读写面、post-read、独立写回状态、保存 checkpoint、停止与恢复。

单主控不发明案件因果，不代替现实研究，不以项目状态判断文学质量，不以正文技巧提升门禁，不模拟用户决定，也不把 drafted、MR、confirmed、synced、PVV、BAV、RTV 或 final 压成 generic done。

专业 owner 固定为：

- `novel-project-strategy`：项目文件、稿件层、状态、确认/同步治理、checkpoint 和恢复。
- `craft-social-mystery`：案件因果、知情/使用权限、线索公平、嫌疑/揭示、现实命题、安全和分幕专业审计。
- `novel-writing`：章节/场景可写性、正文候选、人物/节奏/转场/文风和局部修订工艺。
- User：核心方向、内容边界、重大事实/结构变化、精确 A4、formal 章节确认、同步授权和独立会话授权。

## 3. 真相源与最小恢复

优先级为：用户明确决定 -> current 项目对象/事件/receipt -> 项目 `AGENTS.md` 与状态/恢复包 -> P02 正式协议 -> Skill 默认。聊天摘要、mtime、文件编号和聚合页都不能替代 current 版本证据。

每次恢复按项目 README、current RPM、项目状态、运行登记、证据索引、稿件层清单、当前章合同/ERE/审计/确认同步和必要近场正文的白名单顺序读取。默认不读全稿、未来正文、旧聊天、其他小说或环境秘密。扩展读取必须有唯一缺口、allowed root 和新 manifest version。

## 4. 证据等级

- L1-protocol：协议、模板、值域和预期；证明可表达。
- L2-synthetic：合成场景；证明可判定。
- L3-isolated-file：隔离副本运行；证明文件机制和 fail-closed。
- L4-real-project：真实项目对象、正文、审计、同步和 post-read；证明声明 scope 的实际运行。
- L5-real-user：绑定唯一 object/version/layer/scope 的明确用户决定。
- L6-clean-session：独立新 Agent 只按 RPM 白名单完成恢复和语义 oracle。

低等级不得替代高等级；索引、计划、写入事件或脚本退出码本身不授状态。

## 5. 运行记录

每轮必须建立唯一 Controller Record，至少包含：project/task/run、object/version/revision/scope、active layer/pointer、main route、skill/state/write owner、L0-L4 required/actual/not-read、source fingerprints、A0-A5、gates/conflicts、allowed/prohibited reads/writes、expected/actual evidence、独立状态、stop、checkpoint 和 unique next。

同一 project/scope 不允许两个 current controller run。内容变化必须创建新 content version；记录修订不改变 content version。汇总视图只读派生，不能覆盖 owner 记录。

## 6. 授权

- A0：只读检测和 finding；不得改故事、正文或状态结论。
- A1：可逆计划、记录、checkpoint 和选择性失效；不得写 prose/truth。
- A2：隔离探索；只写隔离 root，不授真实项目状态。
- A3：绑定对象/version/layer/scope/终点的 exploration/raw/revised 正文工作；formal 禁写。
- A4：promotion、重大变化、用户确认和结构同步；每种语义分别精确消费。
- A5：拒绝、安全替代或范围外交接；不得以偏好覆盖安全/事实诚实。

授权不互相包含。A4 不能绕过 evidence、POV、现实、原创或安全门禁。

## 7. 主路由与十二节点

主路由按第一个适用项选择：recover -> safety -> change -> confirm -> sync -> propagate -> boundary -> select -> context -> plan -> research -> draft -> audit -> repair -> promote -> recovery-test -> handoff。每轮只有一个主路由；高优先级冲突存在时禁止低优先级写入。

章节状态机严格为：

`N00 恢复 -> N01 选择章节 -> N02 最小上下文 -> N03 章节合同 -> N04 Evidence-Ready -> N05 场景终检 -> N06 正文候选 -> N07 draft/formal 审计 -> N08 owner 最小修复 -> N09 A4 formal/用户确认 -> N10 required 结构同步 -> N11 传播/分幕/恢复/下一章`

前置已有 current 证据时可以引用，不得跳过证据或继承相邻章门禁。

## 8. 逐章闭环

1. 选择 current CH 和连续窗口，建立 CC/SC/BT/IS/PCE/WH。
2. 对每个现实依赖建立 R/RC/RB/RS/RA/FB/ERE；未 ready 的依赖切片 stop=`research-blocking`。
3. 在 current DR、STY 和精确 A3 下生成 exploration/raw/revised；到授权终点停止。
4. 候选只做 draft-review；finding 回唯一 owner，以新 version 最小修复并局部重审。
5. eligible revised 经精确 A4 晋升 formal；晋升不得改变正文 bytes。
6. current formal 完成 formal-audit，MR 只认 actual position evidence。
7. CFR 披露 version/scope/non-inclusions；只有 L5 CFD 才能 confirmed。
8. confirmed 不等于 synced；SFD/SYP/SYR 后必须逐 target post-read，SYV 全 matched 才 synced。
9. 本章 checkpoint 关闭后，下一章以本章 current CFD/SYV 作入口，但所有门禁独立重建。

## 9. 变化、分幕与恢复

关键变化以 SIH/current actual 为种子，经 CIR/IGS 计算到 object/version/scope/dimension；只失效可达结论，未触及结论用 PEI 保留。PVP ready 不等于 PVV；只有 required consumers post-read 全 matched 才 propagation-verified。

分幕以 BAR/BSS/BAU/BAF/BAV 检查 C01—C12 和反事实。missing input 先记 unresolved；open blocking finding 阻止 BAV，不投票、不猜事实。

恢复以 RPM/RTR/RRR/RTV 分开验证 package、files、workflow、semantic-context 和 clean-agent-session。机械前三维不能提升后两维；clean-agent-session 必须有 L6。pack 在 source/status/next 变化后 stale，必须保留历史并重建。

## 10. Fail-Closed 与恢复动作

缺 current evidence、双 current、source drift、无 A3/A4、错误稿件层、POV/权限越界、现实未 ready、决定性线索未实现、确认歧义、sync partial/conflict、传播 under/over-reach、boundary finding、manifest 外读取或非唯一 next 均停止相关写入。

恢复动作只选一个：resume、replan、rebuild、repeat-audit、route-owner、request-user/A4 或 abandon。相同 root cause 连续两轮无改善即 no-progress，不自动循环。

## 11. 状态与规范证据

- evidence-ready：current ERE。
- manuscript-realized：current formal 的 MRE/MRG 与 formal-audit。
- confirmed：current CFR/CFD + L5。
- synced：current SFD/SYP/SYR/SYV post-read。
- propagation-verified：current PVR/PVV。
- act-boundary-verified：current BAR/BSS/BAU/BAF/BAV。
- recovery-reconstructed：current RPM/RTR/RRR/RTV；semantic/clean 分维记录。
- final-audited：P02 不评价、不授予。

任何状态变化必须有 owner、对象、版本、scope、evaluation、evidence 和 event；新版本不继承旧门禁。

## 12. P02 验证基线

正式关闭基线包括：S01—S09 协议与专项评测；《停更之后》CH07—CH09 三章实际闭环；13 次强制失败；CH09 line 21 变化的 PVV；CH08→CH09 的 BAV；机械恢复与 L6 clean recovery；30 个 S10 集成场景；P01 与 P02-S02—S09 全量回归。

该基线证明 P02 范围的单主控章节生产闭环可长期协作、可验证、可恢复。它不证明 CH10+、其他分幕、全稿质量、出版准备或并发写作。

## 13. 冻结与变更

本协议为 P02 frozen baseline。后续若改变对象语义、授权、状态蕴含、门禁、证据等级或恢复规则，必须创建新协议版本、列 repair delta、计算影响、选择性失效并重跑受影响专项/集成/上游回归。不得原地改写历史结论。
