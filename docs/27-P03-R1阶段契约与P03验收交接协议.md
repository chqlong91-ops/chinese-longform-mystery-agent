# P03-R1 阶段契约与 P03 验收交接协议

- 对象：`P03-R1-STAGE-CONTRACT@v001`
- 阶段：`P03-R1：Agent 运行协议简化与恢复契约修复`
- 前置：`P03-STAGE-ACCEPTANCE-AND-FREEZE@v001 / 9/11 / not-passed`
- 生效范围：P03-R1-S01—S08

## 目标

P03-R1 修复中长篇悬疑小说创作 Agent 的运行协议、状态一致性和恢复契约，使正常创作流程减少不必要的用户授权，同时让项目在跨会话、失败和迁移后仍能恢复到唯一可信状态。

R1 是 P03 后置的有界修复阶段，不是 P03-S11，也不是 P04。它不继续生产、审计或修复 C10，不读取任何真实小说正文。

## P03 交接

P03 的历史结论保持为 9/11、not-passed。P03-AC08 与 P03-AC10 未满足，没有 P03 frozen baseline。C10 保持 `closed-with-known-protocol-defect`。

授权粒度过细、状态面漂移、非原子写回、恢复依赖冲突和 object/hash 交互负担进入 R1 repair-input。C10 内容、旧授权文本、项目恢复包和真实项目 L4/L5/L6 只保留为 historical evidence，不成为 R1 当前输入。

R1 的合成结果不得追认 P03-AC08/P03-AC10，不得创建或补写 `P03-FROZEN-BASELINE@v001`。

## 修复需求

R1 必须完成以下能力：三级停点收敛、唯一 canonical state、多维状态分离、原子事务和生成视图、Skill-aware manifest、读取账本、恢复构建/装载/验证、历史兼容、强制失败、诚实验收及安全 nonclaims。

需求编号和 owner 以 `P03-R1-REQ@v001` 为准。R1-AC01—AC08 的终裁只在 S08 完成，S01 契约不得自授验收通过。

## 三级停点原则

一级自主覆盖普通规划、验证、可逆实现和内部状态维护；二级只用于候选内容及创作方向确认；三级只用于外部、不可逆、重大真相/结构变化或明显范围扩张。permit、lease、controller、checkpoint 和普通 hash 核验保留为内部事务，不形成默认用户门禁。

`docs/25-三级权限与自主执行协议.md` 在 S02 successor 验证并原子提交前继续有效。

## 状态与恢复原则

canonical state 是唯一机器真相源；generated view 只能从它派生。历史证据、当前状态和会话缓存必须分离。恢复 manifest 必须声明真实运行依赖，并分列 project payload reads、environment reads、forbidden reads 与 over-reads。

L6-S 只证明合成恢复协议；L6-P 只由真实项目内容承载型恢复证明。两者不得继承或混同。

## 访问与写入边界

R1 默认只读取和修改 Agent 本体、合成 fixture、schema、工具与 R1 工作记录。C10 和其他小说的正文、候选稿、formal、全稿、sidecar payload 及冻结恢复包均禁止读取或修改。所有 R1 任务的小说读写预算为 0/0。

## 失败关闭

输入漂移、缺件、双 current、部分写入、循环自证、generated view 冒充 canonical、未声明依赖、over-read、L6 类型混同、非唯一下一步或基线回归失败时不得授予状态。相同阻塞连续两次无新增证据时登记 no-progress，并路由给唯一 owner。

## 验收与 nonclaims

R1-AC01—AC08 全部通过前不得创建 `P03-R1-FROZEN-BASELINE@v001`。R1 通过只允许进入 P04 审查，不代表 P03 追认、真实小说恢复通过、Agent 产品完成或泛化已经验证。

本协议由 S01 的 24 个契约场景、12 个隔离强制失败和 21 个既有基线验证支持。它冻结修复契约，但不实现 S02—S08 的治理、状态、事务、恢复或迁移能力。
