# P02 章节审计与最小修复协议

## 文档信息

- 所属阶段：P02 章节规划与正文生产闭环原型
- 对应任务：P02-S07
- 状态：已冻结
- 冻结日期：2026-08-14
- 上游：`docs/06` 至 `docs/11`
- 下游：P02-S08 至 P02-S10

## 目标与边界

本协议建立章节或明确切片级的分层审计与最小修复闭环，使 Agent 能对唯一稿件对象、版本、层和范围回答：审计依据是什么、正文实际实现在哪里、问题为何成立、由谁修复、哪些结论失效、何时重审，以及唯一下一步是什么。

S07 只负责审计请求、审计运行、正文实现证据、发现、处置、修复分流、局部重审、失效和恢复。它不静默改写正文，不创建或提升 `formal`，不执行用户确认或结构同步，不运行分幕、三章黄金路径或全稿终审，也不授予 `final-audited`。

## 七类事实分权

| 事实 | 唯一规范证据 | 不代表 |
|---|---|---|
| 候选可交审 | current S06 PRH、DCE 与 raw/revised MS | formal、正文已实现 |
| 候选审读完成 | current draft-review AUR 与 ADP | formal-audit、MR=yes |
| 可请求正式晋升 | draft-review 的 formal-promotion-request | formal 已创建、用户确认 |
| formal 已晋升 | 未来 S08/A4 的 formal-promoted 事件 | 正文实现、确认、同步 |
| 正式正文已实现 | S07 对 current formal 的 MRE/MRG | 确认、同步、全书通过 |
| 可请求确认复核 | formal-audit 的 confirmation-review-request | 用户已经确认 |
| 用户已确认/已同步 | 未来 S08 的独立确认与同步事件 | MR、final-audited |

这些事实保持独立状态；相邻状态、文件层标签、用户泛化认可或工作完成均不能相互推断。

## 实施顺序与运行顺序

S07 在 P02 实施顺序中先于 S08，因此本阶段只用合成 current-formal 夹具验证 formal-audit 协议。真实项目运行顺序固定为：

1. S06 产生 current raw/revised 候选和 PRH；
2. S07 运行 `draft-review`；
3. 若需修复，回 S06 产生新的 revised MS，再重新 draft-review；
4. 候选满足条件时，S07 只形成 `formal-promotion-request`；
5. S08/A4 执行合法 formal 晋升；
6. S07 对 current formal 运行 `formal-audit`；
7. 若需修复，仍回 S06 新建 revised 版本，再经历新的晋升和正式审计；
8. 正式审计满足条件时，S07 只形成 `confirmation-review-request`；
9. S08 独立处理确认与同步。

不得把实施顺序误当作真实稿件的运行顺序。

## 双层审计入口

### draft-review

- 只接受 S06 PRH 指向的 current raw/revised MS。
- 检查候选是否忠实实现规划、证据、现实、连续性、文风和场景职责。
- 可输出修复要求、阻塞、不可用或 `candidate-ready-for-formal-request`。
- 无论文本质量多高，都不得评价为 `MR=yes`，其 MRG evaluation_state 保持 `not-evaluated`。

### formal-audit

- 只接受未来由 S08/A4 合法晋升的 current formal MS。
- 必须重新读取 current formal 的实际位置，不能继承 draft-review 结论。
- 可对精确章节或切片范围评价 Manuscript-Realized。
- 可输出修复要求、阻塞、不可用或 `formal-ready-for-confirmation-review`。
- 不创建确认、同步或 final-audited 事实。

### 入口预检

每个 ARQ/AUR 至少验证：

1. 唯一 CH/MS object_version、层、scope 和 active pointer；
2. audit_type 与目标层匹配；
3. 来源指纹、稳定位置和审计基线 current；
4. CC/SC/BT/IS、PCE/WH、ERE、STY、CR/CL/CV 与权限范围可消费；
5. RRS 完整并能追溯到规范来源；
6. 输出许可、stop condition、checkpoint 与唯一下一步明确；
7. 无双 active、旧指纹、错层、错版本、范围漂移或 blocking conflict。

任一关键项不可唯一判断时停止受影响范围，记录 blocked/conflict，不按文件时间、编号、篇幅、文质或旧聊天猜测。

## 审计范围与上下文

审计范围使用 S03 的 L0-L4 与稳定位置协议：

- L0：ARQ、AUR、CH/MS/层/版本/scope、许可、终止与 checkpoint；
- L1：项目硬约束、POV/权限、ERE、STY、安全与原创边界；
- L2：目标切片全文及判断所需的近场正文；
- L3：必要远场结构、线索、时间线、人物知情和连续性切片；
- L4：默认排除未来正文、无关章节、旧稿和旧聊天。

审计按最小可判定 scope 运行。局部上下文不足时只扩展一个 blocking claim，达到 no-progress 条件后停止，不转为无边界全稿扫描。

## 正文实现证据与门禁

### Required Realization Set

RRS 将 CC/SC/BT/IS、PCE/WH、ERE、STY、人物/POV/连续性要求转换为逐项 required realization。每项至少记录来源、版本、scope、叙事职责、允许命题、必要限定、禁止项、预期位置和阻塞级别。

### Manuscript Realization Evidence

MRE 的结果只允许：

- `present`：在合法位置以足够可见、可解释形式实现；
- `missing`：要求存在但目标与必要近场均无实现；
- `misplaced`：存在，但位置使其迟到、越界或无法承担职责；
- `overstated`：正文命题强于来源或 ERE 许可；
- `conflicting`：正文与 current 来源、权限或连续性冲突；
- `indeterminate`：证据或上下文不足，不能安全判断；
- `not-applicable`：有明确理由证明本 scope 不适用。

每条非 `missing` MRE 必须绑定稳定 actual location；`missing` 必须记录被检查的期望位置和必要近场。流畅、篇幅足够、DCE 通过、用户喜欢或 formal 文件存在都不能替代位置证据。

### Manuscript-Realized Gate

MRG 将 `value` 与 `evaluation_state` 分开：

- value：`yes | partial | no | n/a`；
- evaluation_state：`not-evaluated | in-progress | evaluated | stale | conflict`。

`yes` 只允许在以下条件同时成立时写入：目标是 current formal；scope 与 RRS 完整；所有 blocking required realization 都有 current MRE；没有 missing/misplaced/overstated/conflicting/indeterminate blocker；审计输入指纹有效；AUR 已完成；不存在阻塞发现。

候选稿只可记录观察，不可得到 `MR=yes`。新 MS version 不继承旧 MRE/MRG。章节或切片结论不得自动聚合为幕级、全书级或 `final-audited`。

## 悬疑、公平、信息权限与现实审计

### 因果与选择

审计真实时间线、行动条件、人物选择、代价和后果是否形成闭合因果；倒序叙述不能掩盖实际因果缺口。若移除关键选择后结局不变，需检查人物能动性或伪因果。

### 公平线索六项

决定性线索逐项检查：

1. presence：在 payoff 前确实出现；
2. visibility：读者有合理机会注意；
3. interpretability：当时至少存在一种合法理解路径；
4. independence：不完全依赖结尾供述或后补事实；
5. uniqueness：与其他解释的区分足够，或明确需要线索组合；
6. source timing：来源、取得和可用时间不晚于角色使用。

结尾解释不得首次提供解答必需事实。重复出现不自动提高独立性，隐蔽不自动等于公平。

### POV 与信息权限

分别检查观察机会、注意、理解、记忆、披露、引用/公开/采信、使用权限与确定度。人物不得使用其未接触或无法理解的信息；受限 POV 不得泄漏 Agent 全知，也不得无理由略过其必然注意的决定性事实。

### 嫌疑人与揭示

主要嫌疑人的进入、加强、校正、退出和残留必须由外部证据或因果变化支持，不得只凭自辩退出。揭示阶梯要区分新事实、新解释和人的反应；供述只能闭合已有证据，不得成为唯一证明。

### 现实、连续性、原创与安全

- 现实主张不得超过 ERE 的 capability、适用范围、命题强度和 qualifier；未决项按 conservative fallback 处理。
- 检查时间、地点、身体/情绪、物件/权限、人物在场、知识、称谓、语言和场景状态连续性。
- 负证据必须证明观察条件和记录完整度，不能把“未见”直接写成“不存在”。
- 命名参考只允许抽象高层机制，不模仿个人声音、句法或标志性情节结构。
- 危险信息只保留叙事选择、非操作性限制和后果，不提高伤害、隐匿、毁证或规避能力。

## 人物、场景、节奏、文风与可读性审读

### 人物进入

核心人物首次有效登场至少使读者能回答：是谁、为何在场、与当前事件或 POV 有何关系、第一印象是什么，并提供至少一个外部特征和一个行为/语气特征。背景不得一次性倾倒；非核心人物按职责使用更轻锚点。

### 场景与节拍

每个目标场景或不可分割节拍组检查 input、人物目标、阻碍/压力、行动或选择、required delta 与 next cause。只有氛围、解释或闲聊而没有状态变化的场景，记录为具体位置化发现，不以泛化“节奏差”替代诊断。

### 转场、张力与章尾

转场应保留时间、地点、POV、行动或因果锚点。高张力段至少可辨认接近/准备、限制/犹豫、风险、决定和即时后果。章节或切片结尾必须形成信息、危险、关系、压力、决定或主题状态变化，并产生 forward pressure；纯停止不算推进。

### 对话与可读性

对话检查说话者可辨、意图/潜台词、信息权限、关系变化和场景职责。说明、内心和动作须服务当前体验，避免把线索、公务知识或人物背景压成作者说明。

### 文风合同与纹理保护

按 current STY 的 scope、继承、覆盖、保留和禁用项审读叙述语法、句段节奏、词汇/register、对话/心理/观察、感官/修辞、说明/证据与格式。具体观察、身体感、暧昧、停顿和语言节奏若承担人物、声音、信息、张力或氛围功能，默认保留；修复优先局部手术，不把文本压成摘要。

统计与评分只用于定位异常，不能独立裁决。个人审美偏好不得伪装为硬错误；每个问题必须回到可观察位置、项目合同、叙事职责或读者理解后果。

## 审计发现与处置

AF 至少记录：对象/版本/scope、稳定位置或明确缺失位置、category、观察、违反规则、读者/因果/公平/现实/风格后果、severity、gate_effect、root owner、最小修复、可选加强、保留约束、重验范围和状态。

severity、gate_effect、owner 和 finding status 相互独立。严重度用于优先级和分流，不用机械总分决定通过。禁止只写 `generic passed`、`节奏不好`、`不够悬疑` 或无法定位的评价。

draft-review 的 ADP 只允许：

- `candidate-ready-for-formal-request`；
- `repair-required`；
- `incomplete`；
- `blocked`；
- `not-applicable`。

formal-audit 的 ADP 只允许：

- `formal-ready-for-confirmation-review`；
- `repair-required`；
- `incomplete`；
- `blocked`；
- `not-applicable`。

一个运行只产生一个 current ADP；历史处置不可原地覆盖。

## S08 交接

AH 只有两种：

- `formal-promotion-request`：来自满足条件的 current draft-review；
- `confirmation-review-request`：来自满足条件的 current formal-audit。

AH 必须携带 ARQ/AUR、MS/层/版本/scope、来源指纹、ADP、未关闭发现、MRE/MRG（适用时）、保留约束、风险、禁止推断和唯一下一步。S08 必须独立复核授权和 current 状态；AH 本身不执行晋升、确认或同步。

## 最小修复、分流与局部重审

RPC/RPD 先冻结 source finding、root cause、preserved constraints、new/changed claims、最小影响范围、owner、授权入口和 re-audit scope，再进入修复。

owner 路由固定为：

- S06：正文局部改写、文风或表达实现；
- S03：稿件层、版本、上下文、稳定位置或活动指针；
- S04：章节合同、场景、节拍、信息窗口或章节结构；
- S05：现实研究、证据能力或命题强度；
- P01：案件因果、人物权限、线索、嫌疑、揭示或结局结构；
- S08：formal 晋升、确认或同步状态；
- S09：后续分幕/跨会话压力范围；
- safety：无法安全保留的操作性危险细节。

S07 不直接改正文。正文修复必须回 S06 以 `rewrite-local` 和新 A3 产生新的 revised MS。即使来源是 formal，也不得覆盖 formal；修复后依次重新 draft-review、S08/A4 晋升和 formal-audit。

先修最早偏离和最小因果切片。修复只使关系可达的 MRE、MRG、AF、ADP、AH 和消费者资格 stale；无关结论保留，历史证据不删除。重审先验证新版本、来源指纹和影响分析，再运行受影响检查。

若同一根因连续两轮修复没有新增证据、范围收敛或处置变化，标记 `no-progress`，停止自动循环并回 root owner 或请求用户决定。不得通过扩大润色范围掩盖上游故障。

## 失效、冲突与恢复

以下变化触发关系可达失效：MS 内容/版本/层、CC/SC/BT/IS、PCE/WH、ERE、STY、POV/权限、连续性、CR/CL/CV、稳定位置或 S08 状态变化。新版本不继承旧审计、确认、同步或门禁。

双 active ARQ/AUR/MS、入口层不匹配、来源指纹过期、稳定位置漂移、旧 PRH、范围重叠处置冲突、快照与事件不符时，设置 conflict 并停止受影响范围。恢复不能按文件更新时间或文本质量猜测 current。

新会话最小恢复集：工作区指南和本协议、状态/事件、current ARQ/AUR、CH/MS/层/版本/scope、RRS/MRE/MRG、AF/ADP、RPC/RPD/AH、来源指纹、checkpoint、阻塞、最近完成点和唯一下一动作。先解析身份和指针，再读取最小 L2/L3。
