## 总目标与 P02 责任

Agent 的长期目标是：建立一个可长期协作、可验证、可恢复的中长篇中文悬疑小说创作 Agent，能够把故事种子逐步推进为逻辑成立、线索公平、正文可读且项目状态一致的完整小说。

P02 负责其中的章节生产段：把 P01 已通过的案件蓝图和章节地图转成可重复的逐章规划、证据准备、正文起草、正文审计、修复、用户确认、结构同步和恢复闭环。

P02 的完成不等于完整小说完成。P02 使用同一案件至少三个相邻章节证明闭环可重复，并为后续全稿工作保存逐章证据、分幕审计和恢复入口。全稿 `final-audited` 留给后续阶段。

## 阶段范围

### P02 直接负责

- 章节作为主要工作对象；
- 章节状态、稿件层、确认、同步和恢复；
- 从结构级章节地图建立章节合同和场景计划；
- 当前正文切片的 `evidence-ready`；
- 受合同、POV、信息权限、文风和现实边界约束的正文；
- 从正式正文验证 `manuscript-realized`；
- 章节修复、用户确认、结构同步和关键变化；
- 分幕连续性、代表性失败案例和跨会话恢复。

### P02 只建立接口

- 全稿 `final-audited` 所需的逐章实现证据、分幕审计和未决研究项；
- 后续全书节奏、终稿修订和出版准备的恢复入口；
- 将章节状态聚合为全书状态所需的对象关系。

### P02 范围外

- 无人值守生成并自动定稿完整书稿；
- 多 Agent 并行写章和多人并发合并；
- 全稿 `final-audited`、出版、排版、投稿和营销；
- 模仿特定作者的个人文风或标志性结构；
- 把未核实的专业主张写成确定事实；
- 提供提高现实伤害、毁证、隐匿或规避追查能力的操作细节。

## P01 交接入口

一个案件进入 P02 正式章节生产前，至少满足：

1. 当前案件结构对象 `design-plausible=yes`。
2. 核心创作方向由真实用户明确确认；`fixture-confirmed` 不计入。
3. 章节地图存在，并可追溯到时间线、知情、线索、嫌疑和揭示。
4. 当前章节的决定性现实依赖已进入研究清单。
5. 项目状态、产物清单、恢复包和最近变化没有未解释冲突。
6. 活动章节、允许的正文范围和稿件层可判定。

第 4 项可以为 partial/no，但它会阻止依赖该能力的正式正文。规划、研究、保守退路和不受影响的工作仍可继续。

## 真相源与最小读取

| 信息 | 活动真相源 |
|---|---|
| 工作、确认、同步、风险、稿件层和门禁 | 项目/章节状态文件 |
| 项目规则和创作边界 | 工作区指南、项目配置和本地合同 |
| 真实因果 | 真实时间线 |
| 人物可观察、理解、披露和使用的事实 | 知情与使用权限矩阵 |
| 线索命题和生命周期 | 线索台账 |
| 嫌疑阶段与责任校正 | 嫌疑路径 |
| 揭示顺序和双重结局 | 揭示阶梯与结局产物 |
| 结构级章节任务 | 章节地图 |
| 现实能力、访问、命题和退路 | 研究清单 |
| 最新关键变化 | 变更记录和受影响规范文件 |
| 读者实际看到什么 | 当前正式正文 |
| 新会话入口 | 恢复包；不得覆盖以上更具体真相源 |

章节任务默认只读取：工作区入口、活动状态、最近相关记录、当前章结构切片、必要的相邻结构、当前现实依赖，以及任务需要的近场全文。默认不读取全稿、无关未来章节、全部历史草稿或旧聊天。

## 请求判定

每个请求归入一类：

1. `范围内`：前置条件满足，可进入章节闭环。
2. `条件范围内`：完成不受阻塞的部分，受影响分支停在门禁。
3. `范围外可交接`：保留已有产物，转到 P01 或后续阶段。
4. `硬边界`：拒绝危险、侵权或虚假事实部分，提供安全替代。

判断顺序为：恢复与环境、关键变化、P01 结构有效性、真实确认、现实依赖、当前章节任务、范围与安全边界。结构前置已满足时引用证据，不重复 P01；发现核心结构故障时先回 P01 修复，不能用正文润色掩盖。

## 授权与确认

### Agent 可以自主执行

- 与当前请求相关的只读检查和最小恢复；
- 文件组织、编号、链接和非破坏性验证；
- 已获准任务内的可逆规划；
- 把不确定专业事实加入研究清单；
- 发现关键变化后计算影响范围；
- 在保留约束下优先提出局部修复。

### 可以暂定但必须隔离

- Provisional 章节合同、场景计划和非决定性表面细节；
- 未确认文风选项和篇幅预算；
- 未核实现实能力的研究问题；
- 明确标记的探索片段。

这些内容不自动进入正式稿、结构真相或 yes 门禁。

### 必须明确确认

- 核心因果、世界规则、内容边界、责任、结局或多章结构的重大改变；
- 将指定正文版本提升为 confirmed；
- 将探索或章节局部事实晋升为结构真相；
- 同步会影响多个下游章节的变化；
- 撤销或替换已经确认的章节事实。

有效确认记录必须写明对象、版本、内容、范围、不包含事项、同步授权和记录位置。

“继续”“可以”“不错”“很好”默认只授权上一轮已说明的安全可逆下一步或表达反馈，不自动成为创意确认、正文确认、结构同步或门禁通过。

## 十二节点章节闭环

| 节点 | 核心动作 | 通过证据 | 主要停止状态 |
|---|---|---|---|
| N00 恢复或初始化 | 恢复环境、活动章、层级、门禁和下一步 | 唯一当前任务 | recovery-conflict |
| N01 选择章节 | 明确章节、版本、任务和边界 | 活动任务记录 | structure-blocked |
| N02 装载上下文 | 读取最小结构与近场正文 | 实际读取清单充分 | context-insufficient |
| N03 章节合同 | 定义任务、POV、信息、人物、状态和依赖 | 要求可追溯且章尾有变化 | needs-structure-repair / pending-confirmation |
| N04 证据准备 | 核验决定性现实能力和主张范围 | evidence-ready 或获准退路 | research-blocking |
| N05 场景规划 | 建立场景卡、节拍和信息顺序 | 每段有功能，POV 成立 | needs-replan |
| N06 正文工作 | 在获准层级写指定切片 | 没有越过合同和权限 | draft-incomplete / safety-stop |
| N07 正文审计 | 检查实际呈现、公平、POV、人物、结构、文风和现实 | 正式正文位置证据 | needs-repair |
| N08 最小修复 | 局部修复并重跑触及检查 | 修复差异和回归证据 | research-blocking / needs-structure-repair |
| N09 用户确认 | 记录明确对象、版本和范围 | 有效确认记录 | pending-confirmation |
| N10 结构同步 | 更新获准且可达的结构真相源 | 文件实际匹配确认内容 | pending-sync / sync-conflict |
| N11 恢复与下一章 | 写回状态、记录和恢复入口 | 新会话可恢复唯一下一步 | recovery-gap |

## 生产门禁

| 门禁 | P02 规则 |
|---|---|
| `design-plausible` | 当前结构因果、权限、线索、嫌疑、揭示和结局在纸面成立；不代表正文成功 |
| `creative-confirmed` | 用户确认明确对象和范围；不代表现实正确或结构已同步 |
| `evidence-ready` | 当前正文切片的决定性现实能力、故事依据、字段、时效、访问、命题、限制和退路充分 |
| `manuscript-realized` | 项目认定的正式正文在允许 POV、时机和命题边界内实际呈现所需事实 |
| `final-audited` | 完整正式书稿通过全稿审计；P02 不提升此状态 |

五门禁按对象记录 `yes`、`partial`、`no` 或 `n/a`，并附范围和证据。完整项目、案件、幕或计划写作的章节没有正式正文时，`manuscript-realized=no`；只有门禁对对象类型确实不适用时才用 `n/a`。

## 草稿、审计、确认和同步

- 草稿可以接受 `draft-review`，产生具体修复意见。
- `draft-review` 不等于 `manuscript-realized audit`。
- `manuscript-realized` 只根据项目认定的正式正文版本和可追溯位置判定。
- 用户可以确认一版尚未审计的正文，但状态必须记录为 `confirmed-but-pending-audit`；`manuscript-realized` 保持 no/pending，结构同步保持 pending。
- 主闭环只有在正文审计通过后才进入结构同步。
- 从 Provisional 章节地图可以建立 Provisional 章节合同；正式起草要求核心方向已确认，并且当前章节合同或明确写作范围已获授权。无需先确认全部未来章节。
- 正文确认、结构同步和五门禁始终分开。

## 停止和跳步

P02 使用以下停止状态：`structure-blocked`、`context-insufficient`、`research-blocking`、`needs-replan`、`needs-repair`、`pending-confirmation`、`pending-sync`、`sync-conflict`、`recovery-conflict`、`safety-stop`、`stage-handoff`。

跳过 P01 结构时回到 P01；跳过现实门禁时阻止受影响精确正文；跳过正文审计时不能提升 `manuscript-realized`；跳过确认时不能晋升结构真相；跳过同步时不能让依赖新事实的下游章节继续。

只阻塞受影响的章节、场景、线索或主张。困难、工作量大、存在研究项或可逆假设本身不构成全项目阻塞。

## 变更、修复和恢复

关键变化先记录保留约束、新旧事实和影响图，再撤销变化可达的状态。变化涉及核心因果、权限、决定性线索、现实能力或结局时，重跑被触及的因果、权限、公平、现实、原创和安全检查。未受影响章节与门禁保持原状态。

正文局部修改至少撤销该切片的 `manuscript-realized`，并根据确认范围判断正文确认是否失效。现实能力变化撤销受影响 `evidence-ready` 及依赖它的正文实现状态。

新会话从文件恢复。恢复包、状态和最近记录发生冲突时，生成恢复差距并停止受影响写入；不得用旧聊天或全稿扫描掩盖冲突。

## Skill 分工

| 职责 | 主责 |
|---|---|
| 悬疑因果、知情权限、线索、嫌疑、揭示、公平推理、决定性现实主张和悬疑修复 | `craft-social-mystery` |
| 工作区、章节状态、稿件层、确认、同步、变更记录和跨会话恢复 | `novel-project-strategy` |
| 章节合同、场景、人物首次登场、正文、修订、文风连续性和具体章节审读 | `novel-writing` |
| 选择主任务、提供最小输入、维护文件与状态、处理交接和停止条件 | Agent |
| 核心创作决定、正式正文确认和重大重构授权 | 用户 |

任何 Skill 的结论只在其职责范围内有效。项目治理不能替代正文判断，正文技巧不能替代状态与恢复，悬疑结构成立不能替代正文实际呈现。

## 决策状态与下一入口

### Confirmed

- 本文中的 P02 目标、范围、P01 交接、授权、闭环、门禁、停止和验证规则。
- P02 不授予全稿 `final-audited`。
- 评测夹具的确认不继承为真实小说创意确认。

### Open

- 具体试点案件和三个相邻章节。
- 项目文风合同和正式章节确认表达。
- P02 新增路由、状态字段、目录、模板和校验工具的具体实现。

### Blocking

- 当前无 S01 阻塞。
- 进入试点正式正文前，真实方向确认和当前章节决定性现实依赖可能构成局部阻塞。

唯一下一入口：拆分 `P02-S02`“定义章节对象与多维状态模型”为 E 级任务。S02 不得改变本文冻结的阶段边界。
