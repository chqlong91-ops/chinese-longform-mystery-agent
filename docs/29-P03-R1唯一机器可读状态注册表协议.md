# P03-R1 唯一机器可读状态注册表协议

- protocol：`P03-R1-CANONICAL-STATE-PROTOCOL@v001`
- schema：`P03-R1-CANONICAL-STATE-REGISTRY@s001`
- registry：`CSR-AGENT-P03R1@v001`
- status：current
- effective date：2026-08-26

## 目的

Canonical registry 是其声明 coverage 内唯一的机器状态真相源。文件名、目录、mtime、自然语言“最新”和 Markdown 摘要都不能授予 current、confirmation、sync、risk、gate 或 unique next。

文件负责长期记忆，会话负责执行。新会话先读 registry 和它声明的恢复入口，不依赖旧聊天重建状态。

## 初始 Coverage

v001 只权威覆盖：

- `agent-governance/current`
- `agent-control/p03-r1`
- `agent-control/p03-r1/task/P03-R1-S03`

小说项目、章节、稿件、全书对象和 legacy P01—P03 control 均不在 coverage 内。它们保持原协议下的 historical/read-only 状态，等待 S07 adapter；coverage 外状态不得被本 registry 猜测或继承。

## Identity 与 Current

每条 object 保存 namespace、object type、object ID/ref、version、record revision、scope、lifecycle、predecessor、owners、states、evidence、relations 和 nonclaims。

current pointer key 固定为 `namespace|object_type|scope`。同一 key 最多一个 current，target 必须在同 registry 内、identity/scope 匹配且 lifecycle=`current`。最高版本、文件顺序和修改时间均不创建 current。

新 semantic version 不继承 predecessor 的 confirmation、sync、risk 或 gate。历史对象保留，不删除。

## 多维状态

registry 分开保存 work、confirmation、sync、risk、gate、lifecycle 和 governance decision。每项带 value、evaluation、owner、scope、evidence、intent 和 non-implications。

work completed 不推出 confirmed、synced 或 gate yes；confirmed 不推出 synced；synced 不推出内容正确；risk normal 不推出证据就绪；governance decision 不授小说或项目状态。

unknown 与 not-evaluated 不同。前者表示已经知道存在未知，后者表示评价尚未运行。

## Owner、Evidence 与 Lineage

authority、state、evidence 和 next owner 分开记录。owner 只负责路由，不证明状态。

Evidence 必须绑定 source fingerprint、scope、支持命题和不能支持的相邻命题。generated view、摘要和待验收对象不能循环证明 registry。

关系显式记录 source/target、scope、dimension、requiredness、evidence 和 status。orphan、cycle、scope mismatch、stale current 和 evidence 断裂均 fail-closed。

## Unique Next 与停止

active registry 必须有一个 unique next。它要么是一个 action 与 owner，要么是一个 blocked action、owner 和 remedy。空 next、多个主 next 或 coverage 外未授权动作不能提交。

安全、证据、source drift、双 current、owner 缺失、非唯一 next 和 coverage 冒充是内部阻塞，不能靠用户授权绕过。

## 查询与派生视图

只读查询先验证完整 registry，再按 namespace、object type、exact scope 和 current 过滤。结果稳定排序，不修改输入。

README、AGENTS、任务页和恢复入口是 transitional/derived view。S04 实现生成器前由 E10 一次同步；发生冲突时 view stale，registry 不被反写。

## Transition Intent 与 S04 边界

S03 定义 intent 的 idempotency key、target pointer、expected/proposed current、preconditions、affected dimensions、evidence、status 和 next。preflight-passed 不等于 committed。

S04 才实现 staging、CAS、single writer、跨文件原子提交、失败回滚和 view generation。S03 的 bootstrap 是一次性初始 snapshot，不证明通用事务能力；bootstrap 后的 registry mutation 必须等待 S04。

## 验证

S03 以 36 个状态场景、20 个隔离强制失败、确定性查询重放和 21 组历史回归验证协议与实现。失败路径不授状态，C10 与其他小说 reads/writes 为 0/0。

## Nonclaims

本协议不实现原子事务、自动视图、Skill-aware recovery、legacy adapter 或真实小说迁移，不终裁 R1-AC03/R1-AC04，不追认 P03-AC08/P03-AC10，也不创建 R1/P03 frozen baseline。
