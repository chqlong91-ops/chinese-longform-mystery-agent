## 章节地图到合同

章节地图拥有结构级分配，CC 拥有当前版本写作约束。每个 CC 字段必须使用一个 mapping_mode：

- `inherited`：原义继承活动结构主张；
- `elaborated`：不改变命题的可写细化；
- `provisional-local`：隔离的可逆局部暂定；
- `change-request`：会改变结构，只记录影响并等待 P01/A4；
- `unresolved`：来源缺失/冲突，停止受影响范围；
- `prohibited-inference`：没有授权且不得推断。

每个字段记录来源对象/版本/位置、来源命题、保留限制、决定状态、授权和验证。CC 至少包含：父 CH、地图来源、主/次任务、POV、时空边界、必需人物、信息槽、entry state、exit delta、forward pressure、R-*、开放项和下游入口。

同一 CH/范围最多一个 active CC。CC 存在不等于 planned；planned 不等于 confirmed、synced、evidence-ready、A3、正文或 manuscript-realized。

## 悬疑信息槽

IS 类型按需启用：

- required-presentation、forbidden-disclosure、continuity-carry；
- clue appearance/reinforcement/reinterpretation/payoff/red-herring-role；
- suspicion entry/escalation/correction/exit/residue；
- reveal answer/contradiction/responsibility-shift；
- pressure reward/threat/alternative/choice/cost；
- emotional-recontextualization。

每个 IS 记录 source claim、visible fact、supports、does_not_establish、earliest_allowed、latest_required、forbidden_before、source_first_fully_accessible、payoff window 和四个信息平面：agent-operational、viewpoint-access、reader-knowledge、output-permission。

POV 权限分 observe、interpret、remember、disclose、use；知道不能推出可引用、备案、公开或机构采信。输出许可复用 S03 的 internal-only、user-report、prose-constraint、prose-hint、prose-disclosure、safe-summary-only。

IS assignment_state 只使用 unassigned、assigned、deferred-with-authority、planning-conflict、retired。assigned 不表示正文已实现。

决定性线索在规划期检查 presence、visibility、interpretability、independence、uniqueness、source timing；这不是 formal 正文的公平性终审。强嫌疑人的进入、秘密、外部校正、责任修正、退出与残留必须有结构来源；红鲱鱼必须基于真实事实而非污名。

## 场景与节拍

每个 SC 记录父 CH/CC、顺序、前置关系、来源指纹、时空、POV、唯一主功能、至多一个次功能、entry state、BT、exit delta 和事件。

SC 主功能可选：锚定压力、引入人物/力量、追求目标、检验嫌疑、取得/错失、重释证据、改变权力/关系、压力下选择、升级危险、揭示/重构、后果/承诺。

每个 BT 满足：

```text
input state + action/pressure -> output delta -> next cause
```

至少记录 actor/goal、input、非操作性动作、阻碍/代价、IS operation、output delta、next cause、R-* 与安全边界。

每个 active SC 至少改变 information、pressure、relationship、danger、decision、thematic-understanding 之一。事件数量、移动或对话本身不算推进。

场景顺序除 sequence index 外，还要有 causal、information、pressure、physical-continuity、contrast 或 reveal-window 依据，依赖图不得成环。time/location/POV/goal 变化必须有转场锚点。

SC 拆分/合并创建新 ID，重排创建受影响对象新版本并重算 predecessor、窗口、entry/exit、reader state 和 continuity。改变章节边界默认回 P01/A4。

## 规划检查与最小修复

PF 必须记录 target、evidence、failure、consequence、minimum repair、new claims、revalidation scope、severity、stop 和 status。

检查依赖顺序：合同目的 -> 信息权限 -> 场景/delta -> 人物首登 -> 转场/连续性 -> 高张力 -> 负载/重复 -> 章尾 -> 社会压力/情感 -> 现实/安全接口。

重点失败：no-main-job、equal-priority-overload、dead-scene、repeated-interview、motion-without-change、character-entry-naked、unanchored-transition、state-jump、compressed-climax、premature-motive-explanation、mere-stop、decisive-clue-after-payoff。

重要人物首次有效登场至少给身份/角色、当前事件/POV 关系、第一印象；核心人物另有一个可识别特征。高张力至少规划接近/准备、约束/犹豫、风险、决定动作、即时后果和 exit delta，不用操作性伤害细节补张力。

最小修复先固定保留约束，定位最早失败字段/关系，选择补锚点、改 IS、合并/拆分/重排或回上游；创建新版本并只重跑可达检查。

## PCE 与 planned

PCE evaluation 使用 not-evaluated、partial、sufficient、stale、conflict。PCE 记录目标 CC、SC/IS 成员、来源指纹、required checks、covered、missing、blocking、PF、R-*、allowed work、L4 排除、next read 和唯一动作。

PCE=sufficient 要求：对象和来源唯一/current；CC 主次任务、POV、人物、entry/exit/forward 完整；blocking IS 已分配/获准延后；公平窗口成立；SC/BT 有功能/delta/无环顺序；blocking PF 关闭；R-* 已识别并限定范围；决策状态和安全边界清楚。

现实依赖未核验但问题和影响完整时，PCE 可 sufficient、work 可 planned、RH 可 ready；受影响 WH 仍 research-blocking。若现实能力会改变核心计划且无合法备选，PCE=partial。

只有 `planning-completed` 原子事件可将 work 改为 planned；事件只改变 work，其他维度不变。成员/来源变化后 PCE stale，旧 planned 证据不能消费。

## 停止与局部继续

| 情况 | stop | 主下一步 |
|---|---|---|
| 活动来源唯一但缺失/过期 | context-insufficient | 定向读取一个最小来源 |
| 上游因果/权限/线索/地图冲突 | structure-blocked | 回 P01 最小修复/change-request |
| CC/SC/IS 自身目的/窗口/顺序/delta 不成立 | needs-replan | 创建局部修订版本 |
| R-* 未核验且影响精确场景 | research-blocking | 交 S05/合法退路 |
| 核心细化等待用户决定 | pending-confirmation | 请求明确对象/版本/范围 |
| 危险、侵权或虚假事实要求 | safety-stop | 安全替代/拒绝越界部分 |
| 活动对象/版本不唯一 | recovery-conflict | 解析对象与事件 |
| sync 目标不一致 | sync-conflict | 交 S08 解析 |

只阻塞依赖可达范围；未受影响的可逆规划和 RH 准备可继续。

## S05/S06 交接

RH 包含 R-*、consumer scope、narrative function、capability/fields/timing query、access/use、supports/does_not_establish、当前假设、fallback need、安全边界、来源和 S05 return contract。S04 不填写核验结论。

WH 包含 CC/SC/BT/IS 版本、候选 MS 范围、POV/信息槽、entry/exit、人物锚点、连续性、近/远场、R-* 状态/退路、保留约束、Open/Provisional 和 S07 验证入口。WH eligibility 只是可以请求 S06；A3、文风合同、MS 和正文由 S06 决定。

## 失效、冲突与恢复

变化先记录 old/new claim、preserved constraints、seed、traversed edges、affected/preserved objects、invalidated dimensions、new claims、revalidation 和唯一动作。

只沿有效且语义匹配的 depends-on、realizes、derived-from、supersedes、invalidates 等关系撤销可达 CC/IS/SC/BT、PCE、RH/WH 和专业状态。新版本不继承确认、同步、planning audit 或任何门禁。

恢复入口增加 active_contract_ref、active_scene_ref、PCE、PF、RH/WH、source fingerprint 和 planning event。恢复顺序：指南/协议 -> 恢复包/项目状态 -> 章节状态/冲突 -> 层清单 -> CC/SC/IS/PCE -> planning events/PF/handoffs -> CR/CL/CV -> 最小结构源。默认不读正文。

双 active CC/SC、来源指纹不一致、顺序成环、entry/exit 冲突、stale PCE/WH 使用均停止受影响范围；不得按版本号、mtime、文本质量或旧聊天猜测。
