# P04 状态驱动创作编排器协议

- protocol：`P04-CANONICAL-STATE-ORCHESTRATOR@v001`
- scope：`P04-S03-E01—E10`
- production evidence：`P04-AC03`、`P04-AC09`

## 控制边界

编排器只负责恢复、路由、能力 dispatch、单步事务、checkpoint 和 next/stop。P01、P02、P03 冻结协议继续决定专业产物和门禁；adapter result 必须携带 capability、outcome 和 evidence，runner 不伪造内容结论。

## 唯一输入

路由只消费 current project canonical registry、声明的 capability catalog 和 task-bound request。聊天、生成视图、目录、mtime 和最高版本不能授予阶段状态。

## 决策顺序

`internal fail-closed → recovery → Tier 3 stop → Tier 2 stop → change → confirmation → sync → current-stage capability → stage handoff → terminal`。

每轮恰好输出一个 route 或 stop；冲突 signal、双 current、source drift、缺 evidence、非唯一 next 立即停止。

## 阶段切换

P01→P02、P02→P03 和 P03→COMPLETE 都要求 current stage 同时满足 work completed、gate yes/evaluated、confirmation confirmed/evaluated、sync synced/evaluated。任何单项不能替代其他项。

## Skill dispatch

catalog 为每个阶段声明 primary/supporting Skill、owner、required context、forbidden context 和能力标识。runner 只创建 dispatch envelope；专业 owner 返回 adapter result。跨 Skill 结论不得越出其职责范围。

## 原子步骤

单次 request 绑定 project、registry path/hash、mode 和幂等键。runner 取得 single-writer lock，做 CAS，最多应用一个 adapter result，通过临时文件原子替换 registry，再 post-read。重放返回既有 receipt，writes=0。

## 停止与恢复

停止类型包括 fail-closed、research-blocking、tier2-confirmation、tier3-exception、no-progress 和 terminal。恢复动作只能是 resume、repair、replan、rebuild、route-owner 或 abandon。checkpoint 保存 source hash、route/stop、owner 和 unique next，不保存小说载荷。

## 非目标

本协议不执行真实小说，不自动确认创意或正文，不批准 Tier 3，不实现 S04 用户交互呈现/遥测，不选择试点，不执行 L6-P。
