# P04-S03 审查与 E 级任务拆分协议

## 1. 任务身份

- task：`P04-S03：实现 canonical-state-driven P01→P02→P03 创作编排器`
- predecessor：`P04-S02-ACCEPTANCE@v001`、`P04-PROJECT-INITIALIZER-BASELINE@v001`、`P04-S02-S03-HANDOFF@v001`
- direct production evidence：`P04-AC03`、`P04-AC09`
- final acceptance owner：`P04-S10`
- current action：审查并拆分 E01—E10，不执行实现

## 2. 审查结论

S03 原目标成立，但必须把“编排”与“专业创作方法”分开。编排器只消费 project canonical state，选择唯一阶段、主路由与能力适配器，运行一个可提交步骤，原子写回 evidence/state/checkpoint，并生成唯一 next 或明确 stop。

本任务作以下收敛：

1. P01、P02、P03 的冻结协议继续定义案件设计、章节生产和全书闭环；S03 不复制或改写专业方法。
2. 编排器以文件和 project registry 为长期记忆，不依赖聊天历史、mtime、目录最高版本或生成视图。
3. 每轮只运行一个主路由、一个 current controller 和一个原子状态步骤；自动下游循环的用户交互体验与遥测归 S04。
4. S03 必须识别 Tier 2/Tier 3 stop signal，但不代替用户确认，也不扩大例外权限。
5. P01→P02→P03 阶段切换必须由 current gate/evidence/confirmation/sync 条件决定，不能由文件存在或 generic done 决定。
6. E08—E09 只使用 synthetic project state，不选择真实试点、不读写小说、不执行 L6-P。

## 3. E 级任务

`P04-S03-E01`：冻结 S03 输入 exact-set、需求、非目标、证据等级与读写预算。

`P04-S03-E02`：定义 orchestration request、controller run、step result、checkpoint 与事件 envelope。

`P04-S03-E03`：建立 P01→P02→P03 阶段能力目录、入口/退出条件与禁止推断矩阵。

`P04-S03-E04`：定义唯一主路由选择器、优先级、Skill/owner dispatch 与最小上下文合同。

`P04-S03-E05`：实现 P01/P02/P03 输出到 project canonical state 的 transition adapter 与选择性失效规则。

`P04-S03-E06`：实现单步 workflow runner、preflight、single-writer、幂等、原子提交与 post-read verification。

`P04-S03-E07`：实现 checkpoint/resume、stop taxonomy、no-progress 与 deterministic unique-next。

`P04-S03-E08`：建立跨阶段 synthetic workflow fixtures 与 fail-closed/恢复场景矩阵。

`P04-S03-E09`：运行可执行 tracer、状态转换、断点恢复、幂等与回归验证，形成 AC03/AC09 生产证据。

`P04-S03-E10`：完成 S03 验收、冻结 orchestrator baseline 并建立 S03→S04 handoff。

## 4. 固定执行顺序

`P04-S03-E01 → E02 → E03 → E04 → E05 → E06 → E07 → E08 → E09 → E10`

不得因局部实现方便跳过 envelope、阶段条件、Skill dispatch、原子 runner 或恢复语义。

## 5. 验收候选

S03 通过至少要求：

1. canonical state 是唯一路由输入，生成视图和聊天不能授状态；
2. P01、P02、P03 阶段入口/退出和 required gates 可机器判定；
3. 每轮唯一主路由、唯一 owner、唯一 current controller、唯一 next/stop；
4. Skill dispatch 输入、最小读取、输出和 authority boundary 明确；
5. 原子 step 不产生 double-current 或 partial state；
6. 同请求重放不重复运行专业动作或重复写状态；
7. 中断后只依靠 checkpoint 和 manifest 恢复；
8. Tier 2/Tier 3、research-blocking、source drift、missing evidence、no-progress 均 fail-closed；
9. synthetic tracer 覆盖 P01→P02、P02→P03、正常步骤、确认停点、失败和恢复；
10. novel reads/writes 保持 `0/0`，真实试点和 L6-P 保持未执行。

## 6. 非目标

本轮不运行 E01—E10，不实现 S04 用户停点体验和遥测，不选择/准入 S05 试点，不运行真实 P01/P02/P03，不读写小说，不修改冻结的 P01—P03 协议，不创建 P04 frozen baseline。
