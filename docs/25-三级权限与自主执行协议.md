# 三级权限与自主执行协议

## 1. 目的

本协议把“用户决定创作方向”与“Agent 执行可逆工作”分开，取代把每一个内部门禁都变成用户授权点的旧交互方式。

旧协议中的 A0—A5、task-bound permit、lease、read/write set、checkpoint 和 fail-closed 继续作为 Agent 内部事务控制与审计证据；除本协议列出的三级停点外，它们不再要求用户逐条签发。

## 2. 一级：Agent 自主执行

在用户已经圈定的小说项目、阶段目标和可写 sidecar 内，Agent 可以自主完成：

- 最小上下文恢复、对象/hash/状态核验与定向结构读取；
- 章节 N00—N05 规划、证据预检、官方或权威原始来源研究及保守 fallback；
- 不改变核心真相的局部 A3 最小修复、no-change 或 revised candidate 物化；
- repair delta、局部复验、审计、状态、证据索引、恢复入口和 checkpoint 写回；
- 用户确认候选稿后的 A4 整章评价、formal 晋升、CFD、结构同步、SYV、L4-C、相邻边界和批次聚合；
- 在 source drift、双 current、证据不足或范围扩张时 fail-closed，并给出最小补救。

一级动作必须可逆、只写已授权项目的工作区或 sidecar，不覆盖 protected source，不改变案件核心因果、责任人、决定性线索身份、幕结构或结局。

## 3. 二级：用户确认

以下节点必须停下并请用户确认，但只需要简洁确认，不需要长授权书：

- 新建或修订后的正文候选稿；
- 两个以上会导致明显不同阅读体验的创作方向选择；
- 章节或全书的内容确认；
- 全书终稿确认。

候选稿确认只确认绑定 object/version/hash 的正文内容。确认后，若后续评价没有触发三级例外，Agent 自动完成 formal、CFD、同步和成员评价，不再逐门请求授权。

## 4. 三级：例外明确授权

只有以下事项需要用户提供明确授权或决定：

- 改变责任人、核心因果、关键真相、决定性线索身份、世界规则、幕结构或结局；
- 覆盖、删除或回写 protected source、原章节、合并稿或其他不可逆对象；
- 扩展到用户未圈定的小说、目录、私人数据或新的外部系统；
- 对外发布、传输、交付、release 或其他产生外部影响的动作；
- 启动独立新 Agent/L6 clean-session 验证；
- 任何破坏性、不可逆或会显著扩大成本与风险的操作。

三级停点应由 Agent 主动说明变化、影响、可选项和建议。确需精确授权时，Agent 才输出可复制的授权语句。

## 5. 冲突与停止

- 用户最新明确指令优先于旧的逐门授权记录。
- 旧 A3/A4/L4-C 授权样例保留为历史审计证据，不再定义日常交互节奏。
- permit/lease 由 Agent 在任务内自动创建、消费和释放，不自动扩大读取或写入范围。
- 未触发二级或三级停点时，Agent 应连续推进到可验证产物，不得以“等待授权”代替执行。
- 发生 source/hash 漂移、双 current、必要研究不足、越出当前项目或需要改变核心创意时立即 fail-closed。
