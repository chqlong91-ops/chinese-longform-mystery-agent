# P02 章节对象与多维状态协议

## 文档信息

- 版本：P02-S02 冻结版
- 日期：2026-08-14
- 上游：P02-S01 阶段契约、P01 状态基线、Agent 总目标
- 适用范围：P02 章节规划与正文生产闭环的对象、状态、证据、历史、聚合、失效和恢复基础
- 状态：已冻结；S03 至 S10 必须引用本协议，不重复定义基础语义

## 目标

本协议让中长篇悬疑小说项目可以长期协作、验证和恢复。章节是主要工作对象；场景、正文切片、线索和现实依赖可以拥有局部证据、门禁、风险和失效范围。

本协议不判断案件逻辑、线索公平、现实能力或正文质量。它要求这些专业判断绑定明确对象、版本、范围和证据，使“逻辑成立、线索公平、正文可读”不能被工作进度或用户喜好代替。

## 阶段边界

S02 负责：

- 稳定对象身份、内容版本和关系；
- 当前状态快照、追加式事件和证据地址；
- 独立状态维度、转换、聚合和禁止推断；
- 关键变化后的局部失效、冲突和恢复快照；
- 状态模板、夹具和契约测试。

S02 不负责稿件层语义、章节合同内容、现实核验、正文生成、正文审计、实际同步、真实变更演练、三章黄金路径或全稿 `final-audited`。

## 对象模型

| 对象 | 标识 | 作用 |
|---|---|---|
| 项目 | `PRJ-*` | 项目入口和对象索引 |
| 案件 | `CASE-*` | 单个悬疑案件结构 |
| 幕 | `ACT-*` | 连续章节和分幕范围 |
| 章节 | `CH-*` | 主要工作、确认、同步和恢复对象 |
| 场景 | `SC-*` | 章节内局部叙事和门禁范围 |
| 正文切片 | `MS-*` | 可版本化、可定位、可审计的正文范围 |
| 线索 | 项目既有 ID，如 `C03` | 线索命题与生命周期 |
| 现实依赖 | 项目既有 ID，如 `R02` | 现实能力、访问、字段和命题 |
| 章节合同引用 | `CC-*` | 连接章节地图和正文生产 |
| 结构产物 | `ART-*` | 时间线、知情、线索、嫌疑、揭示和地图等真相源 |

已有 P01 ID 原样保留。新对象 ID 创建后不可复用；文件改名或移动不改变对象 ID。

## 对象引用、版本和修订

规范引用：

```text
<object_id>@<object_version>#<scope>
```

三类序号分开：

- `object_version`：内容版本；
- `state_revision`：当前状态快照写回修订；
- `event_seq`：单对象追加事件顺序。

文件路径是 `artifact_ref`，不是对象身份。状态范围不得大于证据范围。正文实际修改创建新内容版本；新版本不继承旧版本的确认、同步或门禁 yes。

## 关系

| 关系 | 方向与用途 |
|---|---|
| `contains` | 父对象包含子对象，只用于范围计算 |
| `depends-on` | 消费者依赖线索、现实能力或结构事实 |
| `realizes` | 场景或正文实现章节合同或结构任务 |
| `evidenced-by` | 状态或判断由证据支持 |
| `synced-to` | 已确认事实需要写入结构目标 |
| `derived-from` | 新对象来自拆分、合并或重构 |
| `supersedes` | 新版本或对象替代旧版本或对象 |
| `invalidates` | 变化事件撤销明确状态范围 |

关系记录源、目标、版本、范围、创建事件和有效性。只有与变化类型匹配的关系边传播失效。

## 状态记录分工

| 记录 | 活动职责 |
|---|---|
| 项目状态索引 | 项目活动指针、对象入口、项目风险和派生摘要 |
| 章节状态快照 | 章节及局部对象当前有效状态、证据、冲突和下一步 |
| 状态事件记录 | 状态为何、在何种授权下从旧值变为新值 |
| 恢复包和总览 | 从活动状态生成的入口摘要，不覆盖活动真相源 |

结构事实由 P01 对应文件拥有，用户决定由确认记录证明，现实能力由研究证据证明，读者实际看到什么由当前正式正文证明。

## 证据地址

每项非初始状态至少引用：

- evidence ID 和类型；
- 被支持的对象、版本、范围、维度和值；
- 项目相对文件路径和稳定位置；
- 来源版本、记录主体和时间；
- 支持命题及不支持的内容。

证据类型包括 structure-audit、user-confirmation、research-audit、formal-manuscript-location、sync-diff、change-impact、recovery-check 和 mechanical-test。不同类型不能相互代替。

## 独立状态维度

| 维度 | 规范值 | 回答的问题 |
|---|---|---|
| `lifecycle_state` | active、superseded、retired | 对象是否仍活动 |
| `work_state` | not-started、planning、planned、drafting、drafted、auditing、needs-repair、revising、audit-complete、paused | 工作操作做到哪一步 |
| `decision_state` | open、provisional、pending-confirmation、confirmed、rejected、blocking | 创作选择是否已决定 |
| `confirmation_state` | not-requested、pending、confirmed、changes-requested、withdrawn | 用户是否确认指定版本和范围 |
| `sync_state` | not-required、pending、partial、synced、stale、conflict | 必需结构目标是否实际写回 |
| `risk_state` | normal、revisit、blocked、conflict | 当前对象风险程度 |
| `stop_status` | none 或 S01 十一种停止状态 | 受影响范围为何停止 |
| `active_layer_ref` | 对象引用或 none | 当前允许读写哪个稿件层对象 |
| 五门禁记录 | 独立记录 | 专业生产门禁的对象化结论 |

`drafted`、confirmed、synced 和任何门禁不得相互推断。`confirmed-but-pending-audit` 是 confirmation、manuscript 和 sync 的派生标签，不是规范总状态。

## 停止状态

S02 使用：`structure-blocked`、`context-insufficient`、`research-blocking`、`needs-replan`、`needs-repair`、`pending-confirmation`、`pending-sync`、`sync-conflict`、`recovery-conflict`、`safety-stop`、`stage-handoff`。

辅助表达规范化：

- draft-incomplete -> work=drafting；
- needs-structure-repair -> structure-blocked 并记录原因；
- recovery-gap -> 可从状态恢复时 risk=revisit，不能唯一恢复时 recovery-conflict。

## 五门禁记录

每项门禁记录：value、evaluation_state、对象版本和范围、覆盖、缺口、阻塞、证据、判断者和时间。

- value：yes、partial、no、n/a；
- evaluation_state：not-evaluated、pending、evaluated、stale、conflict；
- partial 必须列出 covered、missing 和 blocking；
- pending 不是 value；使用 no/partial 加 evaluation=pending；
- 计划写作的章节没有正式正文时 manuscript=no；
- P02 不提供 `final-audited=yes` 的合法事件。

## 状态事件

状态只由原子事件改变。一个事件只修改一个对象版本、一个范围和一个维度。多维变化使用同一 bundle ID 关联多条事件。

事件至少记录：event ID、event_seq、类型、状态、对象、维度、前后值、触发、主体、A0-A5 授权、证据、失效与保留范围、发生和记录时间、唯一下一步。

已 applied 事件不能原地修改。错误通过 `state-corrected` 或新失效事件纠正。相同 event ID 与相同内容重复提交是 no-op；相同 ID 不同内容产生 recovery-conflict。

## 授权边界

- A0：只读检查、冲突识别和审计发现；
- A1：对象创建、可逆规划、研究项、状态记录和局部失效；
- A2：隔离探索；
- A3：明确范围的正文创建或修改；
- A4：用户确认、晋升、结构同步和重大重构；
- A5：越界请求，只能拒绝、交接或提供安全替代。

授权先于转换。普通“继续”只推进已经说明的安全可逆下一步。

## 聚合与禁止继承

聚合必须声明父对象、维度、范围、当前成员版本、适用成员、排除理由、来源修订、覆盖、缺口和阻塞。聚合结果是派生视图，来源变化后立即 stale。

- work 只汇总分布，不生成“全书完成”；
- decision 和 confirmation 不自动聚合 confirmed；
- sync 只在所有明确目标实际写回后聚合 synced；
- risk 汇总最高风险和对象清单，不反向修改子对象；
- design 的子对象覆盖不能替代父级结构审计；
- creative 只能由覆盖目标范围的真实用户确认支持；
- evidence 和 manuscript 只在 declared scope 内聚合；
- final 不在 P02 聚合或提升。

旧版本、父子对象、相邻章节、章节地图、用户确认、研究结果、探索对象和 fixture 均不能自动传递状态。未触及旧证据只有经过 change-impact 和当前版本新事件才能重验证。

## 失效与冲突

关键变化先记录新旧事实、保留约束、seed objects、关系边、受影响状态、保留状态和重验项，再追加失效事件。

正文局部修改至少撤销修改切片的 manuscript，并让新版本 confirmation 初始化为 not-requested。现实能力变化撤销依赖范围的 evidence 和 manuscript。未到达对象保持原状态。

双活动版本、双活动层、快照事件不符、确认范围不明、sync 与目标不符、门禁证据过期、正文结构不一致和恢复包过期均有独立冲突记录。冲突只停止其影响范围。

## 恢复快照

恢复快照至少包含：来源修订、项目与当前路由、活动章节、范围和层引用、独立状态维度、五门禁、开放冲突、必要证据、最小下一读取和唯一下一动作。

恢复包过期但项目/章节状态和最近事件一致时，从活动状态重建恢复包。活动对象、版本、层或下一步不唯一时设置 recovery-conflict，不扫全稿或旧聊天猜测。
