# P03 唯一全稿装配与来源校验协议

## 协议身份

- protocol：`P03-UNIQUE-ASM-ASSEMBLY-PROTOCOL@v001`
- requirement baseline：`P03-S07-REQ@v001`
- source manifest/profile：`P03-ASM-SOURCE-MANIFEST@v001`
- controller：`P03-ASM-ASSEMBLY-CONTROLLER@v001`
- entry/read permits：`P03-ASM-ENTRY-READ-PERMIT@v001`
- deterministic build：`P03-ASM-DETERMINISTIC-BUILD@v001`
- verification：`P03-ASM-SOURCE-STRUCTURE-VERIFICATION@v001`
- publish/state：`P03-ASM-ATOMIC-PUBLISH@v001`
- change/recovery/handoff：`P03-ASM-CHANGE-RECOVERY-HANDOFF@v001`
- downstream interface：`S07-S08-FULL-BOOK-AUDIT-INPUT@v001`
- downstream handoff：`S7H-P03-S08@v001`
- status：frozen；protocol evidence=`L1-L3`

## 目的与边界

本协议把 current formal narrative members 转换为唯一、可追溯、不可静默改文的 Assembled Manuscript（ASM）。闭环固定为：

`Source Admission -> Candidate Build -> Two-Stage Read Control -> Source/Structure Verification -> Atomic Publish -> Independent State/Handoff`

S07 只装配和校验来源、版本、顺序、payload、包装与结构，不修改 truth、formal、schedule、LCG、progress、BAV/LAV，不执行 S08 整书语义/文艺审计。ASM 存在、可打开、count/hash 匹配、validator 通过或用户鼓励都不能证明 `final-audited`。

## 证据等级

- L1：需求、schema、owner、状态机、non-claims 可表达。
- L2：56 个合成场景得到唯一规范判定。
- L3：22 个隔离文件夹具验证 exact-set、permit、build/SGM、verification、CAS、state、失效和污染=0。
- L4-A：未来全部 required boundary 的 current BAV 与实际 boundary positions。
- L4-B：未来 current LCG D01-D11、current LAV 与实际 source/consumer positions。
- L4-C：未来每个 required member 的 current formal、owner evidence、source fingerprint/post-read。
- L4-M-build：绑定 planned candidate + ASMF 的 exact source byte assembly；正文不进入模型上下文。
- L4-M-verify：candidate 形成后绑定其 ref/hash 的完整 source/structure verification。

L1-L3 最高证明 protocol-ready/evaluated，不能生成真实 ASMF/ASM/AVV/current/state。两次 L4-M permit 均 task-bound、不可继承；S08 必须另行签发 full-book semantic read permit。

## Source Admission 与 ASMF

ASMF 绑定唯一 project/book/ASM scope/planned ASM version、current BK/BP/BSN/PAM/BAM/LCG/S06 handoff、assembly profile、source watermark 与 expected/actual/not-read exact sets。

expected membership/order 只来自相同 current basis 的 owner manifests，不从目录、glob、mtime、文件数、自然排序、旧全稿或口头“全了”反推。member type 为 owner 显式声明的 front-matter-narrative、prologue、chapter、interlude、epilogue 或 appendix-narrative；非叙事版权/营销/工作文件默认排除。

actual member 必须一一对应 expected member，并为唯一 current formal，具有 required ERE/MR/CFD/SYV/CMR/index、chapter-production、boundary、long-range current evidence。missing、extra、duplicate、stale、mixed-layer、conflict 或 unresolved conditional 任一非空即 blocked。count 相等不等于 exact-set matched。

每个 member 至少保存 identity/type/requiredness/order/act/batch/chapter、formal object/version/layer/current event/stable locator、source-byte/decoded/normalized/payload hashes、title/metadata/boundary/structure fingerprint 与 owner evidence refs。

## Assembly Profile 与正文保持

profile 显式冻结 input/output encoding、BOM、line ending、Unicode normalization、title mode、wrapper、separator、metadata allowlist、payload extraction、offset convention、hash 与 canonical serialization。

source-byte、decoded/normalized payload、candidate segment payload 分层验证；wrapper/title/separator/metadata ranges 与 payload ranges 分离。只允许 profile 声明的纯机械转换。禁止改字、改标点、重写标题、删重段、补过渡/线索、调整次序、合并/拆分正文或用旧稿补缺。内容问题回 source owner 创建新 formal version。

## Records、Controller 与 Checkpoint

S07 复用 S02 ASM domain envelope；S7CR、ASMF、ASR、ABR、SGM、AVR、AVV、AWEI、ACP、APV、ASI、S7I 是 operational records，不创建第二种 ASM domain family。

同一 project/book/assembly scope `WIP=1`。合法主路径：

`prepared -> current-resolved -> input-verified -> manifest-frozen -> build-permit-ready -> staging -> candidate-built -> verify-permit-ready -> verifying -> verification-committed -> publishing -> current-committed -> state-projecting -> handoff-evaluating -> committed`

CP0—CP9 分别冻结 prepared、source resolved、manifest、build permit、candidate、verify permit、AVV、current、state 和 handoff。same-intent replay 只复用 post-read matched 的 durable CP；different-intent、double controller/current、out-of-order、cross-version 或 integrity conflict fail-closed。

## Entry 与双阶段 Full-Read Permit

Entry preflight 必须解析唯一 current basis、三类前置 state、ASMF/profile、L4-A/B/C exact sets、WIP、safe absolute staging/publish paths 与 phase write set。preflight 不读取正文 payload。

`L4-M-build` 绑定 planned candidate、ASMF hash、ordered exact source locators、byte-stream reader、staging target、member/byte/open/time budget。只允许生成 candidate/SGM/ABR/mechanical hashes；`model-visible prose bytes=0`。

`L4-M-verify` 只在 CP4 后签发，绑定 candidate identity/locator/length/hash、ASMF/profile/SGM/ABR。只允许 source/structure checks、finding 与 AVV 输出；禁止 FAR 和语义/文艺裁决。

两个 permit 都记录 required/actual/not-read/unexpected、access log、expiry/revocation 和 release receipt。source/candidate drift、budget 超限、path escape、unlisted read/write 或正文 context contamination 立即停止。

## Deterministic Candidate Build 与 SGM

build key 覆盖 ASM identity/version、ASMF、ordered versioned members、profile 和 output-affecting tool contract。算法只按 ASMF order 读取 exact source bytes，验证 source hash，执行 allowlisted decode/normalization，确定性生成 wrappers/separators，并在 intent-specific staging root 写 candidate/SGM/ABR。

SGM 使用 zero-based half-open `[start,end)` ranges，逐 member 保存 source/decoded/payload/segment hashes、wrapper-before/payload/wrapper-after/separator ranges、title/metadata 与 structure fingerprint。全部 ranges 必须 ordered、无 overlap、无 gap并 exact-cover candidate。

相同 build key/source post-read 必须得到相同 SGM/candidate hash；different output 是 integrity failure。candidate 在 CP4 后 immutable，但不是 current；partial/staging residue 不进入 registry/state/handoff。

## Source / Structure Verification

AVR 用 fresh verify permit 独立读取 candidate/source，不继承 build buffer/结论。V01-V32 覆盖：identity/currentness；expected/source/SGM/candidate exact-set；member requiredness/order/type/version/layer；source/decoded/payload/segment/ASM hashes；range exact coverage；title/metadata/encoding/wrapper/separator/boundary；member/global structure fingerprints；staging inventory；permit/access/release 与 final post-read。

AVR 从 ASMF/profile/source 独立流式重建或逐 byte 比较 expected candidate；最终 candidate hash、count 或“看起来完整”不能替代 V01-V32。finding 带 stable source/candidate range、expected/actual、severity、gate effect、唯一 owner、最小修复与 reverify scope。

AVV 值为 matched/blocked/stale/conflict/not-evaluated。只有未来真实 L4-M-verify、V01-V32 全部 applicable matched、open blocking/major=0、unexpected=0、source/candidate post-read与 release 完整，才可 matched。

## Atomic Publish 与 Unique Current

publish 必须满足 candidate/ASMF/profile/SGM/ABR/AVR/AVV/L4 exact tuple current/matched，且 unexpected write=0。固定步骤：PUBLISH-PREPARE、TARGET-PREPARE、TARGET-POST-READ、CURRENT-PREPARE、CURRENT-CAS、CURRENT-COMMIT、FINAL-POST-READ。

current registry key 为 project/book/ASM scope，值保存唯一 current ASM ref/version/content+structure hash、ASMF/AVV/source watermark/current event/revision。旧 current 在 CAS 前保持有效；CAS 后 historical/superseded 并保留 bytes/evidence。target prepared 或 file rename 不等于 current。

CAS conflict 不覆盖 winner；CAS 后无 receipt 时先读 registry/event；final post-read失败则禁止 ASI/S7I。任何 rollback 必须是新 CAS event，不能直接改指针文件。

## `book-assembled` 独立投影

`book-assembled=yes/evaluated` 只由唯一 current ASM、current AVV、APV/CAS/final post-read 与 L4-M actual exact-set投影。partial/no/not-evaluated 分别表达不完整实际证据、已知不满足和未真实运行；stale/conflict 是记录状态。

该状态消费但不反授 chapter-production、act-boundaries-verified、long-range-consistent；与 final-audited、book-confirmed、release、recovery 互不蕴含。ASI 只向 S02 state projector 提交 input，由 projector post-read/CAS；S7CR/validator 不直接写 yes。

## Change、失效与恢复

变化沿显式 relation 计算 reached frontier：

`source/owner evidence -> ASR/ASMF -> permit -> ABR/candidate/SGM -> AVR/AVV -> APV/current -> ASI/book-assembled -> S7I`

新 source/member/profile/tool-output/current version 不继承旧 assembly evidence。未触及项只凭 PEI 的 before/after refs、relation、currentness 与 post-read 保留。旧历史 evidence 不删除，但 stale ASM 不再 eligible for S08。

partial 从 CP0-CP9 最近 durable checkpoint 恢复；resume 必须重做 current/source watermark 和 path/write-set preflight，需要读取时签新 permit。同一 attempt signature 连续两轮没有 evidence/frontier/checkpoint 改善即 no-progress，禁止自动第三轮。

source bytes/title/gates 回 P02；membership/order 回 S03/S05；LCG 回 S04；BAV/LAV/state/handoff 回 S06；manifest/profile/build/verification/publish machinery 归 S07；重大 A4 回 User。

## S08 受限接口

`S07-S08-FULL-BOOK-AUDIT-INPUT@v001` 未来只交付唯一 current verified ASM、ASMF/profile/member source map、SGM ranges、AVR/AVV V01-V32、APV/CAS/final-read、上游三状态、book-assembled state、S07 permit history/release、unresolved/not-read/non-verdicts 和 expires-on-change。

明确排除 candidate、partial、staging、fixture、summary、old/superseded current、stale AVV、raw/revised、legacy、future 和 old chat。S08 必须创建自己的 FAR entry/full-book semantic read permit；S07 L4-M 不继承。

当前 `S7H-P03-S08@v001` 只有 protocol shape，没有真实 S7I/ASM/AVV/state，因此只授权审查并拆分 P03-S08，不授权真实 FAR。
