## 文档信息

- 版本：P02-S03 冻结版

- 状态：已冻结；S04-S10 必须复用，不得重新合并层、状态、确认、同步或门禁

## 目标与边界

本协议让中长篇悬疑小说项目可以从文件恢复当前工作表面、活动章节、正文对象/版本/层、任务所需的最小充分上下文、实际读取证据、明确排除、缺口或冲突，以及唯一下一步。

S03 不规划具体章节内容，不核验现实主张，不生成或审计小说正文，不执行用户确认或结构同步，不运行真实三章试点，也不授予 `evidence-ready`、`manuscript-realized` 或 `final-audited`。

## 工作表面与稿件层

### work_surface

| 值 | 含义 | 活动 MS 要求 |
|---|---|---|
| structure | 案件或章节结构工作 | 无正文任务时 active_layer_ref=none |
| research | 现实依赖工作 | 通常 none |
| manuscript | 正文对象读写 | 写入时必须唯一 |
| audit | 结构、现实或正文审计 | 仅正文目标需要 MS |
| record | 状态、清单、事件或恢复记录 | none；可引用 MS |

`work_surface` 是路由元数据，不是 S02 新状态维度。

### manuscript_layer

| 层 | 用途 | 最低写入授权 | 不代表 |
|---|---|---|---|
| exploration | 隔离试写和方案实验 | A2 | 结构事实或正式正文 |
| raw | 明确范围的原始正文 | A3 | 已修订、已确认或已审 |
| revised | raw/旧 formal 的修订候选 | A3 | 已正式晋升 |
| formal | 项目登记的正式正文表面 | A4 晋升/替换 | confirmed、synced、manuscript=yes |

稿件层与 work、decision、confirmation、sync、risk 和五门禁正交。层更高不证明文字更正确或更可读。

## 正文对象、版本与活动指针

正文继续使用 S02 的 `MS-*`，规范引用为 `<MS-ID>@<object_version>#<scope>`。最小记录包括父 CH/SC、层、artifact_ref、稳定位置、derived-from、supersedes、内容指纹、创建事件和生命周期。

- 文件路径不是身份；改名不创建内容版本。
- 内容变化创建新 object_version。
- 新版本不继承旧 confirmation、sync 或任何门禁 yes。
- 同一写入范围只能有一个 active_layer_ref。
- 结构任务没有正文对象时写 none，旧“活动层=结构”规范化为 `work_surface=structure`。
- 双活动层设置 recovery-conflict，不凭时间、文件名或文本质量猜测。

## 层转换接口

| 操作 | 来源 -> 目标 | 授权 | 结果边界 |
|---|---|---|---|
| explore-created | none/结构 -> exploration | A2 | 只创建隔离 MS |
| raw-created | CC/授权范围 -> raw | A3 | work 独立变化 |
| revision-created | raw/revised/formal -> revised | A3 | 新版本独立初始化 |
| formal-promotion-requested | revised -> 请求 | A3 | 不创建 formal |
| formal-promoted | revised -> formal | A4 | 只改变层/活动指针；其他维度另发事件 |
| promotion-rejected | 请求 -> 无 | A0/A4 | 来源保留 |
| formal-revision-started | formal -> revised | A3 | formal 不被静默覆盖 |
| layer-retired | 任一 -> retired | A1/A4 | 历史保留 |

事件复用 S02 信封和 bundle 规则。S06-S08 仍负责生成、质量条件、正式晋升、确认和同步的专业语义。

## 按主张确定活动真相源

| 主张 | 活动真相源 |
|---|---|
| 实际因果和顺序 | 真实时间线及对应结构产物 |
| 人物观察、理解、披露和使用权限 | 知情与使用权限矩阵 |
| 线索命题、出现和回收要求 | 线索台账 |
| 嫌疑阶段和责任校正 | 嫌疑路径 |
| 当前揭示边界 | 揭示阶梯与章节地图 |
| 现实能力、访问、字段和限制 | 研究证据 |
| 读者实际看到什么 | 当前活动 formal MS 的稳定位置 |
| 工作、确认、同步、风险和门禁 | 项目/章节状态及专业证据 |
| 用户确认内容 | 有效确认记录 |

不存在一条覆盖所有主张的总真相优先级。正式正文证明读者看到了什么，不能覆盖真实时间线或知情权限。

## L0-L4

| 层 | 内容 | 默认规则 |
|---|---|---|
| L0 当前任务 | 请求、路由、对象/版本/范围、表面、层、授权、产物、验证、下一步 | 每轮必需且必须唯一 |
| L1 硬约束 | 项目规则、P02 协议、POV/禁止披露、门禁、保留和安全约束 | 写入或判断任务必需 |
| L2 近场全文 | 目标 MS、必要前后文、必要相邻正文、直接来源稿 | 只有文字/位置判断需要时读取 |
| L3 远场结构 | 当前章及相关时间线、知情、线索、嫌疑、揭示、研究和台账切片 | 按主张和稳定区段读取 |
| L4 冷区 | 无关未来正文、旧草稿、废弃探索、旧聊天、无关案件 | 默认不读；只有具体缺口才能升级 |

装载单位是“对象版本 + 稳定范围 + 用途”，读取粒度为 metadata/index/section/full-object/full-file。不得把 full-file 作为默认。

默认模式是近场全文、远场结构。相邻章不自动全文；未来正文默认 L4；未来揭示约束可作为 L3 internal 结构切片进入。

## 任务装载轮廓

- 恢复：指南、恢复包、项目/章节状态、层清单、最近事件和最近上下文记录；默认不读正文。
- 规划：当前/相邻结构行和相关结构主张；正文只在衔接确需时定向读取。
- 证据准备：R-*、权限和依赖结构；精确核验由 S05 完成。
- 起草：明确 MS 目标和 A3；当前前文、必要近场及相关结构切片；未来正文不读。
- 修订：目标范围、保留约束、足够前后文和被触及结构主张。
- 审计：声明审计类型、目标层/版本/范围、目标正文及相应结构切片；语义由 S07 完成。
- 确认：对象/版本/范围、待确认文本、修订说明和 confirmation 状态。
- 同步：确认记录、formal 位置、sync 目标和当前版本；不从全稿开始。

## 上下文证据

S03 使用：

1. `Context Requirement (CR)`：任务、对象、授权、required claims、L1、L2/L3 需求、L4 排除、扩展和停止条件。
2. `Context Load Manifest (CL)`：实际读取的来源对象、版本、位置、mode、范围、用途、结果和输出权限。
3. `Context Coverage (CV)`：每个 required claim 的覆盖、缺口、阻塞、允许工作、最小下一读取和唯一下一步。

新增 evidence subtype：`context-load` 和 `context-coverage`。它们使用 S02 证据地址，只证明读取和覆盖过程，不替代 structure-audit、research-audit、formal-manuscript-location、user-confirmation 或任何门禁证据。

## 五项独立判断与充分性

每个来源分别判断：loaded、current、authoritative-for-claim、sufficient、permitted-for-output。读取成功不能补偿版本过期、来源不权威、范围不足或输出越权。

CV evaluation：not-evaluated、partial、sufficient、stale、conflict。partial 必须列 covered、missing、blocking、allowed work 和一个最小 next_read。

任务写 sufficient 至少要求：L0 唯一、blocking claims covered、L1 当前、必要 L2/L3 充分、无未处理 stale/conflict、输出权限足够、L4 排除可见、验证和下一动作明确。sufficient 不提升任何生产门禁。

## 定向扩展

1. 选择一个 blocking 且未覆盖的 required claim。
2. 从它的活动真相源定位最小对象/版本/范围。
3. 记录扩展理由、停止条件和仍排除的 L4。
4. 实际读取并只重算依赖该来源的 coverage 行。
5. sufficient、明确阻塞、无进展或达到边界时停止。

CR 默认 max_expansion_rounds=3；相同缺口连续两轮无新增覆盖视为 no-progress。任何任务都必须设置 max_scope 和 forbidden_sources。达到边界时报告 partial 和一个上游动作，不转向全稿扫描。

## 冲突与恢复

| 问题 | 主要判定 |
|---|---|
| 预计来源缺失、路径错误、读取范围不足 | context-insufficient |
| 所读版本 stale 且活动版本唯一 | 定向读取当前版本 |
| 活动对象/版本/真相源不唯一 | recovery-conflict |
| sync=synced 但目标不匹配 | sync-conflict |
| 人物权限记录缺失 | context-insufficient |
| 权威记录明确禁止所需披露 | structure-blocked 或 pending-confirmation |
| 未就绪现实主张要求精确表述 | research-blocking |
| 危险操作化细节 | safety-stop，改为安全摘要 |
| 全稿终审或 S04-S10 实施 | stage-handoff |

恢复包过期但项目/章节状态、最近事件、层清单和 CL 一致时可重建恢复包并标 risk=revisit。它们不能得到唯一活动对象时必须停止，不能扫全稿或旧聊天猜测。

结构与正式正文差异先按主张所有权分类：正文未实现结构要求是 realization gap；正文提出新局部事实保持 chapter-local；正文违背时间线或权限进入结构/修复流程；确认但未同步的变化保持 sync=pending。

## 悬疑信息与披露权限

四个平面分别记录：agent-operational、viewpoint-access、reader-knowledge、output-permission。人物权限进一步分 observe、interpret、remember、disclose、use、reader-visible。

输出许可：internal-only、user-report、prose-constraint、prose-hint、prose-disclosure、safe-summary-only。许可带对象、版本、范围、受众和时间点。

- Agent 读取真相只允许用来守住因果和公平，不能让 POV 使用未知事实。
- 受限 POV 不得无理由隐瞒其必然注意的决定性事实。
- 知道不等于可引用、备案、公开或使机构采信。
- 当前线索可见事实和歧义按 L3 进入；未来正文不因防泄露而全文装载。
- reality-claim 受 R-* 命题限制；context sufficient 不等于 evidence-ready。
- 危险机制只以可观察矛盾、调查收窄、动机和后果安全概括。
