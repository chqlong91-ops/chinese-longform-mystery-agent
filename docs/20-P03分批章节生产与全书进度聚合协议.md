## 目标与边界

S05 将 S03 的确定性生产调度、P02 的逐章 N00-N11、S04 的 LCG 原子更新和 S02 的对象/state 语义串成一个单主控、可暂停、可重放、可恢复的分批生产事务。它使实际运行能逐章取得 owner evidence、同步 actual realization/consumer positions、形成 chapter/batch/act/book 进度与 BSN/state candidate，同时不让聚合覆盖章节 owner truth。

协议开发只证明该机制可表达、可判定、可隔离运行；它没有选择小说、调用真实 P02、读取或写入 manuscript、创建真实对象/聚合、运行 S06 或授予全书状态。

## 四层事实与两层证据

四层事实严格分开：

1. P02 actual chapter evidence：current formal、ERE、MR、CFD、SYV 与适用 PVP/BAV/RTV。
2. S04 LCG current/index-sync：chapter realization/consumer position 的 required mutation 已原子提交，或 owner-backed no-op/NAD 已提交。
3. chapter/batch/act/book progress 与 BSN：从 expected manifest 出发的 exact-set 只读聚合。
4. `chapter-production-complete`：S02 独立 state projector 对全体 planned members 的投影。

协议层 L1-L3 只证明字段、规则、合成判定和隔离文件机制。任何 real production 声明必须 project-bound，实际调用 P02，保存 L4-C chapter evidence 和 L4-B book-structural snapshot；精确确认/重大动作另需 L5，clean-session 另需 L6。fixture、synthetic adapter、summary、文件存在或多个低等级结果不能升级。

## 运行记录

S05 使用六类治理记录：

- `PER`：一个 batch/chapter 复合编排运行；不拥有 P02/S04 verdict。
- `CMR`：一个 chapter content version/formal layer/scope 的 actual evidence receipt；不复制正文。
- `PAM`：chapter/batch/act/book scope 的 expected/eligible actual exact-set 聚合。
- `AMR`：一个 expected member 与 eligible CMR/index evidence bundle 的连接记录。
- `SPEI`：S05 requirement、run、receipt、graph、aggregate、event 的证据索引；与 P02 PEI 分离。
- `PEC`：复合 commit boundary、partial、stop、恢复动作和 unique next 的 checkpoint。

全部复用 S02 public envelope、schema/content/revision/projection、atomic event、Current Registry、CAS 和 post-read。计划、执行、receipt、index、aggregate、BSN 和 state 不共享 identity/current/owner。

## 四 Controller 与复合事务

调用栈固定：

`S03 select/claim -> S05 open/preflight -> P02 dispatch/return -> S05 verify/CMR -> S04 mutation/current -> S05 index verify/aggregate/BSN/checkpoint -> S03 next evaluation`

S03 只拥有 schedule/ready/WIP/CIV，S05 只拥有复合治理记录，P02 只拥有章节/正文/门禁证据，S04 只拥有 graph query/mutation/current。每次调用有 correlation/causation/sequence/idempotency/expected-actual sets 和一次性 token；owner 不随调用转移。

六个 commit point 是 schedule claim、P02 owner commit、CMR commit、LCG current/no-op commit、aggregate commit、checkpoint commit。复合事务以不可变 commit point 和可恢复补偿实现，不伪装跨 owner 的全局回滚。若 P02/CMR 已合法提交而 LCG 失败，必须保留 evidence，停在 `receipt-committed/index-pending`，阻止聚合与 dependent consumer。

同一 manuscript family `write_wip=1`，只有 P02 写阶段可持有；graph 与 BSN 由各 owner 分别 CAS，不与 manuscript lease 同持。等待用户/研究/owner 时释放活动 writer lease。timeout 不自动转权，takeover 必须重验 registry、checkpoint、intent、source 和旧 lease。

## Entry Preflight 与最小上下文

dispatch 前严格执行：current resolution、ready/chosen revalidation、member/predecessor/entry gate、owner/safety stop、LCG query、章节/layer/slice、authorization、expected reads/writes/results、WIP reservation、token final-read。全部匹配才 `ready`；blocked/denied/conflict 不得 dispatch。

`S05-LCG-QUERY-REQUEST` 默认 far-field structure；near-field 只读唯一 current formal 的精确位置；directed expansion 只沿声明 dimension/relation/hop。permit task/run/purpose/position-bound、single-use，不继承。默认不读 full manuscript、未来 prose、旧聊天、其他小说或 manifest 外文件。

A0-A5 不互含。project-bound prose 写入需 exact A3；promotion、重大变化、确认、同步分别需精确 A4/L5。S05 只验证并传递授权，P02 负责消费和写入。

## P02 Actual Invocation 与 CMR

真实 runtime 必须实际消费 P02 N00-N11 trace。已有 current evidence 可以 `reused-current`，但每个节点仍需 actual trace、owner source、authorization、read/write、event、post-read、checkpoint 与 successor。

terminal 值域为 completed、pending-confirmation、repair/research/owner-blocked、paused、partial、stale、conflict、no-progress、abandoned。只有 canonical completed 可进入 receipt verification；generic success/done/passed/exit 0 不合法。

CMR 逐项重读同 chapter/version/layer/scope 的 current formal、ERE、MR、CFD、SYV 与适用 PVP/BAV/RTV，核对 registry/event/fingerprint/expected-actual side effects/WIP release。提交顺序为 prepare、verify、candidate write、post-read、commit、final-read。same key/same intent 返回既有 CMR；different intent conflict；新 content version 不继承旧 receipt。

协议 fixture 强制 synthetic=true、real_project=false、L4-C=false、member_complete=false、state_grants=[]；模拟字段不能创建真实 formal/CFD/SYV。

## LCG Mutation 与 Index-Sync

只有 current `receipt-committed/index-pending` CMR 能生成 `S05-LCG-MUTATION-REQUEST`。manifest 分列 node/edge/source/consumer/position/D01-D11/timing/permission/proposition/requiredness/coverage/provenance。S05 不能发明 truth、权限、命题或语义关系。

disposition 互斥：required、no-op-with-owner-NAD、owner-return、blocked、stale/conflict。空 diff 或关键词未命中不能自动 NAD。

required 路径由 S04 执行 prepare、candidate build、owner review、coverage impact、candidate post-read、current prepare、CAS commit、final verify、sync return。只有唯一 current 与 final-read matched 才 index-synced。no-op 仍需 owner/NAD event/current post-read。graph 失败保留 CMR/P02 evidence，不删除、不降级、不改 expected manifest。

## Progress、BSN 与 State Projection

expected members 只来自 current BP/BPM/BBT owner manifest。member eligible 要求 actual P02 completed、CMR committed、current formal/ERE/MR/CFD/SYV、required index-synced、BBT exit、fingerprint/post-read 全匹配且无 partial/stale/conflict。

chapter/batch/act/book 每级都保存 expected、eligible actual、missing、extra、duplicate、pending、partial、stale、conflict、owner NAD exact sets。数量相等不替代 stable-key exact-set。act chapter progress 与 boundary/BAV 分开；book complete 只是 state candidate。

BSN 在 committed watermark 上保存 current member/evidence/state refs 的不可变 snapshot，按 prepare、candidate、post-read、verify、CAS、final-read 构建。BSN current、PAM complete 或 summary 都不授状态。

`chapter-production-complete=yes/evaluated` 只在完整 current planned chapter set 每个 member 有 L4-C actual evidence、required index sync、book PAM/BSN L4-B、events/post-read matched 时由 S02 projector 授予。partial/no/not-evaluated 分开。它不蕴含 act-boundaries、long-range、assembly、final、confirmation、release 或 recovery。

## 异常、变化与恢复

每个 stop 保存 phase/root cause/evidence/owner/attempt/delta/chosen action/checkpoint/unique next。每轮只选 resume、replan、rebuild、repeat-verify、route-owner、request-user-A4、abandon 一个主动作。

dispatch、P02、receipt、LCG、aggregate/BSN、checkpoint 六类 partial 各从最近 committed boundary 恢复；unknown dispatch 先查 idempotency，P02 commit 后不重跑，LCG CAS 后不重建，BSN CAS 后只 final-read。跨 version/scope 拼接、回滚合法 owner evidence、缩小 expected set 均禁止。

变化沿显式 required relation 的匹配 scope/dimension 计算 reached frontier。preservation 需 old/new basis、owner impact verdict、current/fingerprint/post-read；未列出不等于 preserved。同 root cause 连续两轮无规范 evidence delta 提交 NO-PROGRESS，禁止自动第三轮。

## S06 受限接口

`S05-S06-AUDIT-INPUT@v001` 分列 expected scope 与 actual evidence：current BK/BP/BSN/BPM/BBT/LCG/PAM；每章 formal 精确位置、ERE/MR/CFD/SYV/CMR/index 与 L4-C；act/boundary refs；D01-D11 node/edge/timing/permission/proposition/coverage/error/NAD/change history 与 L4-B；read permit/budget/required/not-read；unknown/unresolved/research/owner return。

plan/fixture/summary 不能进入 actual set，缺 required actual 时 handoff not-ready。S06 必须建立自己的 audit run、读取授权证据并执行因果、连续性、权限、公平、嫌疑、动机、揭示、现实、证据命题、原创和安全审计。S05 index/coverage/PAM/handoff 均不签 BAV、semantic verdict 或 long-range-consistent。

## 验证、冻结与 Non-Grants

[P03-S05 模板](../templates/P03-S05/) 覆盖 6 类资产。`S5M-01`—`S5M-48`、`S5F-01`—`S5F-18` 验证正向、门禁、证据、WIP、幂等、partial、LCG、exact-set、BSN、失效、恢复、no-progress 与 S06 filter；baseline pollution、真实 P02、正文读取和状态 grant 均为零。S05 专项、本地链接、5 个 frozen anchors 与 14 组 frozen regression 零错误。

S05 完成证明生产/聚合协议可长期协作、可验证、可恢复，不证明任何真实小说已生产或全书状态通过。唯一下一入口是围绕总体目标审查并拆分 `P03-S06`；不是运行 S06、正文生产或完整试点。
