# 状态事件记录

## 产物契约

- 用途：追加记录对象状态怎样、为何以及在何种授权下变化。
- 创建触发：任一对象状态发生尝试性或已生效转换时创建事件。
- 更新触发：不得更新已生效事件；纠错必须追加 superseded 事件。
- 写入规则：只追加 applied、rejected 或 superseded 事件；已生效事件不得原地修改。
- 真相边界：事件解释变化历史，当前值仍由项目或章节状态快照拥有。

## 影响

- 失效状态：`<object.dimension.scope|none>`
- 保留状态：`<object.dimension.scope|none>`
- 关联变化：`<change-id|none>`
- 关联冲突：`<conflict-id|none>`

## 写入结果

- 快照写回：`applied|not-applied`
- 新状态修订：`<positive-integer|unchanged>`
- 派生视图需重算：`yes|no`
- 恢复包需更新：`yes|no`

## 校验

- [ ] 事件 ID 唯一，序号连续。
- [ ] 只改变一个对象版本、范围和状态维度。
- [ ] 授权等级足以支持目标动作。
- [ ] 证据范围不小于目标状态范围。
- [ ] 没有跨维隐式晋升。
- [ ] applied 事件已实际写回快照。
- [ ] rejected 事件没有改变快照。
- [ ] 唯一主下一步只有一个。

## P02-S07 事件入口

- Audit request/run：`audit-request-*|audit-run-*`
- Finding/disposition：`audit-finding-*|audit-disposition-*`
- MR：`manuscript-realization-*`
- Repair：`repair-case-*|repair-delta-recorded|repair-re-audit-*`
- Handoff：`audit-handoff-created|audit-handoff-invalidated`

同一 bundle 按 MRE/AF -> ADP/MRG -> work/risk -> RPC/AH 顺序 applied；确认和同步事件不得混入 S07 bundle。

## P02-S08 事件入口

- Promotion：`formal-promotion-review-*|formal-promotion-run-*|formal-promoted|formal-active-pointer-*|formal-audit-return-*`
- Confirmation：`confirmation-request-*|confirmation-decision-*|confirmation-withdrawn|confirmation-invalidated|confirmation-revalidated`
- Sync authorization：`sync-authorization-granted|limited|withheld|revoked`
- Sync：`sync-plan-*|sync-run-*|sync-target-*|sync-verification-*|sync-state-*`
- Compensation/conflict/handoff：`sync-compensation-*|sync-conflict-*|sync-impact-handoff-*`

晋升、confirmation、sync 和门禁事件不得合成一条跨维事件；bundle 只表达关联，仍逐项 applied。

## P02-S09 兼容入口

- 本对象的 stable ID、version、scope、currentness、fingerprint 与引用关系可作为 IGS 节点/边证据；路径或摘要不是身份。
- 本对象变化时，只沿显式 relation 和适用 dimension 形成 affected item；未触及范围必须有 PEI，不能全量清空。
- 若被列入幕边界或恢复白名单，必须引用 current BSS/RPM 条目及稳定位置；本模板自身不证明 propagation、act-boundary、recovery 或 final 通过。
